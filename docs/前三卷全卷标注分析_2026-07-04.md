- 答案为 `艾凡`，输出 `磨粉匠艾凡`，应算对。

- `赫萝 -> 女孩/少女` 是错的。

## 初步结论

1. 第 1 卷的 93% 左右更接近系统当前真实上限；第 2、3 卷严格准确率被答案口径拖低，但即使按姓名包含口径修正，仍只有 82% 和 83%，远没到可接受状态。

2. “有名字必须用名字”应该成为后续标注与验证的核心规范。输出包含姓名的全称、称号加姓名、身份加姓名可以接受；只输出职业、性别、年龄、外貌泛称不能接受。

3. 答案文件也需要被同一规范约束。第 2、3 卷有多处答案写角色身份、模型输出姓名的情况；这些不一定是模型错，可能是答案没有按新原则规范化。

4. 不能为某本小说写特殊规则。后续应做通用机制：从原文、答案、角色状态、证据库中动态建立“姓名/全名/称号/身份”的候选关系，再用于标注提示、Verifier 检查和验证分析。

5. 真正严重的错误仍然是具名角色互换，尤其主角互换、新角色场景中的相邻说话人互换，以及具名角色被标成泛称。这些不是单纯扩展答案候选能解决的，需要后续改进证据检索、对话轮转判断和最终一致性审查。

### 第 4 卷错误归因

1. 具名角色被泛称吞掉。

最典型的是开头艾凡登场：答案是 `艾凡`，模型连续输出 `少年`。日志显示模型确实找到了“少年随即绕到马车前方这么说”这种局部证据，但没有把后续自我介绍 `吉尧姆•艾凡` 反写到之前的“少年”。这正好对应新的标注原则：有名字之后，前文同一角色也应该归一到姓名，而不是继续保留“少年”。

2. 多人群体场景容易把具体说话人退化成群体。

#201-300 的酒吧段是最大低谷，`酒吧老板` 被标成 `酒吧客人`、`村民`、`罗伦斯`、`赫萝`。日志里可以看到模型常依据“有人劝酒”“村民说出恩贝尔”等局部语义，判断成泛群体，却没有稳定追踪“这句到底是老板、某个客人、还是村民群体中的人”。这类问题不能写成某本小说的“酒吧规则”，应做通用的多人场景说话人候选跟踪。

3. 罗伦斯/赫萝互换仍然很多。

第 4 卷主角互换合计 60 条。代表例：L433 `不像在说谎，可是——`，Labeler 认为这是赫萝回答罗伦斯的问题；Verifier 后来纠正为罗伦斯，理由是 L433-L434 是罗伦斯延续分析，L439 才是赫萝明确回应。说明模型太依赖“问答交替”，遇到一个人连续思考/连续发言时容易错。

4. 旁白、叙述者、非人物发声口径不统一。

`旁白 -> 非人物发声` 18 条、`叙述者 -> 非人物发声` 7 条。例如 L1539 `圣遗物`，模型判断为叙述说明，不是人物对话，于是输出 `非人物发声`；参考答案是 `旁白`。这类不一定是语义错误，更像标签体系需要明确：旁白、叙述者、非人物发声是否是同一类，还是分别表示“叙述声音”“拟声/标语/标题/引用”。

5. 引号内引用、内心转述、标题式短语容易误判。

例如 L3333 `对不起` 出现在叙述句中，是罗伦斯心里回想艾莉莎道歉的话。模型输出艾莉莎，参考答案为旁白。这里模型抓到了原始发话人，但没有区分“当前标注目标是否是一句被叙述引用的短语”。这需要通用的 quote type 分类，而不是只让模型猜 speaker。

6. 部分参考答案需要人工复核。

例如 L2984 `艾凡。`，上下文 L2985 明确写“一听到罗伦斯的呼唤，艾凡才想起自己代为保管着皮袋”，模型输出罗伦斯；但参考答案统计中显示为 `艾莉莎 -> 罗伦斯`。这很可能是参考答案错，不能简单归为模型错误。后续七卷总分析应把“明显参考答案疑似错误”单独列出。

### 第 4 卷初步结论

第 4 卷 82.6% 明显不可接受，而且主要问题不是答案短名/全名口径。优先要解决的是通用机制：

- 对已具名角色做前后向归一：先出现“少年/女孩/磨粉匠”等泛称，后续出现姓名时，应能把同一角色回填为姓名。
- 多人场景中维护候选说话人集合，不把具体角色轻易退化成“村民/客人/众人”。
- 减少对简单交替模式的依赖，显式识别连续发言、插入叙述、回应延迟。
- 建立 quote type 判断：普通对话、旁白/叙述、拟声、标题/术语、内心引用、转述引用应先分类，再决定是否需要 speaker。
- 验证时允许短名/全名/称号加姓名，但不能允许具名角色被泛称替代。

### 第 5 卷错误归因

1. 未具名角色标签粒度不一致非常明显。

最典型的是 `女服务生 -> 红发女孩` 30 条。日志显示 L708 的上下文明确写“红发女孩……说”，模型输出 `红发女孩` 有文本证据；参考答案写 `女服务生`，也是合理身份标签。这类并不是“具名角色必须用名字”的问题，而是未具名角色到底用职业、外貌，还是场景身份作标签的问题。后续人工校订答案时，应给这类未具名角色建立候选别名，例如 `女服务生|红发女孩|酒吧女孩`，或者统一一个主标签。

2. 具名角色被身份泛称替代仍然是严重问题。

`伊弗 -> 女商人` 20 条。日志中 L1156 已明确自我介绍“我名叫芙洛儿•波伦……以伊弗•波伦自称”，后续仍输出 `女商人`，按“有名字必须用名字”的原则应算错。这说明系统缺少把“女商人”动态归一到“伊弗/芙洛儿”的稳定机制。

3. 罗伦斯/赫萝互换仍然不少。

第 5 卷 `赫萝 -> 罗伦斯` 23 条，`罗伦斯 -> 赫萝` 16 条，合计 39 条。代表例 L154，Labeler 把 `嗯。什么嘛，大家好像也没有在做生意的样子。` 判成赫萝，Verifier 后来纠正为罗伦斯。错误原因仍是过度依赖局部交替或误读“如赫萝所说”的指代。

4. 罗伦斯/伊弗互换集中在长对话场景。

`伊弗 -> 罗伦斯` 22 条、`罗伦斯 -> 伊弗` 22 条。代表例 L1268：Labeler 认为 `是个爱说话又善于交际的人。` 是罗伦斯延续前句，Verifier 纠正为伊弗，理由是 L1267-L1268 是伊弗连续发言，L1269 才出现罗伦斯反击。这说明连续发言、破折号续句、叙述插入后的发言归属仍不稳。

5. 旁白/非人物发声口径仍需统一。

`旁白 -> 非人物发声` 15 条。例如 L145 `你们该适可而止了吧` 是“马儿甩尾像是在说”的拟人化引用；模型输出 `非人物发声`，参考答案是 `旁白`。这类很可能不是模型完全错误，而是标签体系没有明确“拟人化/引用/叙述短语”应归到旁白还是非人物。

6. 参考答案仍需人工复核。

第 5 卷 82.8% 仍明显不够。与第 4 卷共同指向几个通用改造方向：

- 未具名角色也需要动态别名/描述统一机制，不能只处理有姓名角色。
- 已具名角色必须优先输出姓名，身份泛称只能作为别名证据，不能作为最终标签。

1. 非人物标签体系必须统一。`旁白/叙述/叙述者/音效/非人物发声` 混用会显著拉低严格准确率，验证报告必须单独显示辅助口径，但这不能掩盖真正角色错误。`作者` 是否作为独立 speaker 标签，需要单独定答案规范。
2. “有名字必须用名字”应作为硬规范。只要文本、角色状态或证据库已经证明泛称对应具名角色，最终输出应是姓名；泛称只能作为证据或别名，不应作为最终标签。
3. 不能把这些写成某本小说专用规则。代码层只能做通用机制：识别 quote type、追踪描述词与姓名的动态别名关系、在验证中区分非人物口径与姓名包含关系。

## 本次已实施的通用修复

- Labeler prompt 增加 quote type 前置判断：先区分真实人物发言、叙述/拟声/标题/术语/嵌套引用/假想“仿佛在说”，再决定 speaker，减少把非人物或内心引用误归给附近角色。
- Labeler prompt 强化姓名优先：如果角色有具体姓名，输出姓名；职业、外貌、身份称呼只作为临时标签。若证据显示泛称与姓名对应，最终必须用姓名。
- 临时称呼集合扩展为通用描述词/职业词：如 `女子`、`女商人`、`兑换商`、`磨粉匠`、`店主`、`服务生` 等，触发后续身份调查。这里放的是通用角色描述，不是某本小说的专名。
- 验证报告新增辅助口径：严格准确率保持原样，同时额外显示 `Lenient correct`，接受非人物别名归一和非泛称的姓名包含关系。
- 验证输出新增 `--error-limit`：默认显示前 30 条，`--error-limit 0` 可列出全部错误。

仍未彻底解决的内容：

- 动态别名/姓名归一还主要依赖 prompt 和 SearchAgent，没有形成稳定的结构化别名库闭环。
- 多人场景中的候选说话人集合还不够强，角色互换仍需要后续流程级改造。
- 作者后记、标题、术语、旁白、音效到底统一成哪些标签，需要先定答案规范，否则严格准确率会持续虚低。
- 除第 1 卷外，其他参考答案尚未人工逐条校订；后续分析必须继续标注“参考答案疑似错/候选不足/口径不统一”。

## 后续总体检查建议

第 6 卷因为没有可用参考答案，先不纳入准确率汇总。后续建议统一生成阶段报告：

- 严格准确率、辅助口径、别名候选口径分开统计。
- 按模型来源统计，但避免直接用不同卷横向比较模型。
- 列出每卷最低区间，定位场景级崩溃。
- 汇总“具名角色 -> 泛称”“短名 -> 全名”“角色身份 -> 姓名”“主角互换”“非人物发声误判”等错误类型。
- 对答案文件做一次规范化审计：凡是已具名角色，答案应优先使用姓名，必要时用 `A|B|C` 加入全名、称号加姓名、常用别名。
