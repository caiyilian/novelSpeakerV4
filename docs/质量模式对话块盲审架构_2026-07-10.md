# 质量模式对话块盲审架构

## 目标

质量模式用于通用小说对话角色标注。它只依据当前小说动态读取到的原文、引号位置、说话归属语和已确认的实体证据工作；不得在代码中写入某部小说的人物名、组织名、情节或场景规则。

该模式针对的主要风险是：短句连续对话、多人场景、引号后才出现的归属语、嵌套引号、叙述/心理内容，以及“附近有一个说话动词但它实际属于相邻引号”的错误归因。

## 决策流程

每个目标对话先生成一个无标签的原文证据包：目标引号的精确位置、前后若干对话轮次、轮次之间的叙述边界，以及带行号的原文片段。

随后依次运行五个角色：

1. `QuoteTypeAgent`：只判断目标引号是人物发言、群体发言、叙述/心理、嵌套文本还是声音。
2. `LocalAttributor`：独立检查目标引号前后的归属语，重点区分“发言者”“被提及者”“被问者”和相邻引号的说话人。
3. `BlockSolver`：联合标注本地对话块，允许连续同一说话人，也允许叙述打断交替关系。
4. `CounterfactualReviewer`：读取前三项候选，专门尝试推翻其证据，例如确认说话动词是否其实绑定到另一句引号。
5. `CitationArbiter`：只依据原文及可回查的行号引用作最终选择；弱推断不能推翻有原文引用的一致结论。

前三个判断互相不可见，因此不存在“先给出一个答案，再让其他 Agent 围绕它确认”的锚定问题。第四、五步可以看到匿名候选，但必须回到原文验证其引用。

每个角色通过通用的 `submit_review` 工具提交结构化字段。工具 schema 会按角色要求 `quote_type`、`speaker`、`target_speaker`、`preferred_speaker`、`evidence_basis`、`confidence` 和引用行等字段；模型的自由文本分析只保存在日志中，不能被误写成最终角色标签。

## 记忆策略

短期记忆分为两类：

- 确认锚点：有本地引用支持的直接归属、引号类型判断，或已验证的身份归一结果。
- 暂定结果：所有其他输出。

只有确认锚点允许生成“可能的交替发言”提示。暂定结果仍会记录进日志，但不会作为下一句说话人的依据，避免一次误判沿对话链传播。

## 重试与轮询

质量模式正常情况下每条对话执行五次模型调用；若某个模型没有提交合格的结构化工具参数，会额外触发一次格式修复调用。若使用 `--api-model sense-nova`，每次调用会沿 `sense-nova-1`、`sense-nova-2` 等 Key 轮询。

质量审查的单次请求超时默认 120 秒，可用 `--quality-request-timeout` 调整。轮询池中的某个 Key 出现连接或读取超时时，会进入冷却并立即让下一个 Key 接手，而不是在同一 Key 上重复等待。

## 命令行模式

`ensemble` 是默认模式，`legacy` 保留用于和旧流程做对照：

```cmd
python -X utf8 src\run_label.py --provider api-fallback --data-dir data\volume1 --api-model sense-nova --health-check none --count 9999 --reset-state
```

可选参数：

```text
--decision-mode ensemble|legacy
--dialogue-block-radius 4
--quality-request-timeout 120
```

每轮正式日志会新增 `quality_ensemble` 字段，记录五个角色的结构化结论、最终引用行、是否形成确认锚点，以及最终选择来源。临时日志还会记录模型调用、超时、重试和轮询 failover。

## 验证原则

新架构必须优先在人工复核过参考答案的卷上比较宽松准确率和真实错人数量。严格字符串准确率仍应保留，但全名/简称、已验证别名和非人物标签同义形式必须与真实说话人错配分开统计。
