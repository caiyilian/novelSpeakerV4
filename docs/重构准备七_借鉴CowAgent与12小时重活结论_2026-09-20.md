## 1. 本轮做了什么

### 1.1 借鉴 CowAgent

克隆并研读了 `zhayujie/CowAgent`（44.9k star，MIT，前身 chatgpt-on-wechat）的 `agent/memory/` 模块。可借鉴的核心是 **Deep Dream 蒸馏**：把短期记录周期性蒸馏成精炼的核心记忆（合并/萃取/冲突更新/清理）。这一模式直接映射到本任务的"别名/泛称归并"。

### 1.2 五组新实验（用 v4-flash，未泄露答案）

| 实验 | 结果 |
| --- | --- |
| 逐条精读 + 工具调用 + 账本 + 短记忆（全卷） | 与整卷一致，但单卷 5 小时、五卷 25 小时（**超 12h**） |
| 按幕分块归因（v5） | 88.69%（+0.41pp，微弱） |
| 自我精炼（把首遍喂回去纠错） | 净 0.0pp |
| 别名归一（用账本 alias 表） | v2 −0.56pp（负） |
| **身份消解（把实际输出词表交给模型归并）** | **v2 +1.19pp**（本轮唯一正收益） |

### 1.3 本轮唯一正收益：身份消解

把标注系统**实际输出的标签词表**（不是账本，是真实产出）交给模型做专注的身份归并，再把别名/错字（如「叶克柏→叶克伯」）映射回 canonical：

| 卷 | 引用+账本 | +身份消解 |

| 1 | 94.96% | 94.66%（−0.30） |
| 2 | 91.23% | **92.42%（+1.19）** |

| 4 | 88.98% | 88.98% |

| **合计** | **91.44%** | **91.63%** |

这印证了用户的判断"不要一次输整卷，要分工"——一个**专注的小任务**（身份消解）比整卷标注对别名更敏感。但它只 +0.19pp，不是突破。

## 3. 为什么"弱模型+机械=94%，强模型却到不了 95%"——关键澄清

用户的核心质疑值得正面回答。我现在的理解是：

**旧系统的 17000 行、每条约 15–18 次调用、十几天，是在补偿 sensenova lite flash 的短板**（256K 上下文、推理弱、TPM 低）。它必须逐条读、工具回查、短记忆、角色状态、证据库、复审，才能在弱模型上逼近"整卷一次读懂"。

而 v4-flash 有 1M 上下文 + 更强的推理，**一次整卷读就能到 91.44%**——这已经覆盖了旧系统机械的大部分补偿价值。

**但剩余 3.4pp 不是"机械能补的弱模型短板"，而是 v4-flash 自身的能力边界**。证据：

1. 我把旧系统的核心机制（逐条、工具检索、短记忆、账本）逐一复刻到 v4-flash 上，**没有一个能超过整卷 evledger**——逐条 62%（与整卷持平）、工具检索只被调用 41 次/100 条、短记忆无增益。
2. 剩余错误的两大块对一切机制免疫：**无人称引语欠检测 189 条**（行为墙，7 种方法全失败）+ **实名互换 160 条**（需更强推理）。

**量化天花板**：无人称引语 189 条 = 2.7%，即便完美解决也只到 94.1%；再加实名互换、泛称不一致约 220 条，要 95% 必须把每一类都近乎修满——这正是旧系统用 17000 行才勉强摸到 94.19% 的水平。

## 4. 结论与唯一未测的高价值路径

1. **本轮最优：91.63%（引用+账本+身份消解），每卷约 200 秒。** 离 95% 还差 3.37pp。

2. **"只用 v4-flash、12 小时内、干净方法"到达 95%，证据表明不可行**，理由不是"没花够时间"，而是：
   - 逐条精读（最接近旧系统首遍的方案）已实测：单卷 5 小时、五卷 25 小时**超预算**，且成绩与整卷持平（62% vs 62%）。
   - 旧系统 + v4-flash 的"全套机械"路径，按每条约 15–18 次调用的架构，即使 v4-flash 单次更快，7009 条 × 十万级调用仍远超 12 小时。

3. **唯一还没测、且有理论机会到 95% 的路径**：把旧系统 `run_label.py` 的**完整机械**（逐条深查 + 动态角色状态 + 证据库 + 全卷复审 + 镜像陪审）配到 v4-flash 上跑——因为它已内置 `deepseek-v4-flash` 接入（`_append_opencode_model`）。但这**极可能超过 12 小时**，且需要重新配置并可能改动项目运行状态。
