# Windows 复审断点保存失败修复

第二卷在场景复审中发生 WinError 5：临时文件写入成功，但替换 volume_review_state.json 时被 Windows 拒绝。正式文件可解析，进度为 2017/2259；遗留临时文件同样可解析，进度为 2018/2259。检查时没有第二卷重复 worker，目标文件也没有只读属性。

旧实现只调用一次 os.replace，没有处理短时文件占用。控制台每两秒读取进度文件，在 Windows 上可能与替换发生冲突；杀毒软件等读取者也可能造成占用，无法从异常事后确定具体占用者。

## 修改

- 对 Windows 错误 5、32、33 的文件替换采用退避重试，最多等待 10 秒，首次遇到占用时输出目标与临时文件路径。
- 其他错误直接报告；持续占用超过期限仍报告原异常，不将未保存状态当作成功。
- JSON 采用同目录唯一临时文件，写入、flush、fsync、关闭之后再原子替换。
- 替换最终失败时保留旧断点及完整新临时文件；序列化失败时删除不完整临时文件。
- 复审状态归档及最终标注结果替换也使用同一重试逻辑。
- 保持复审版本和数据格式不变。复审已完成任务先写入 volume_review.jsonl，随后才更新进度，继续运行会利用这些日志恢复。

## 验证与使用

通过 153 项测试、语法检查和角色名硬编码扫描。测试包括真实 Windows CreateFileW 读取句柄阻止删除共享后释放、持续占用保留双版本、非占用错误立即失败和序列化异常保持旧断点。

Windows 控制台版本升级至 v1.0.4。旧 EXE 内置旧代码，需要停止旧进程后在新版点击“继续”；无需 reset，也无需手动将遗留 tmp 覆盖正式状态。其他卷可以在原控制台继续运行，新版仅恢复已经停止的第二卷，避免同卷重复启动。
