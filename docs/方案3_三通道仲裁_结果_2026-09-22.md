记录日期：2026-09-22。分支 `feat/scheme-3-three-pass-arbiter`。方案来源：`docs/discussion/2026-09-21_0935_多Agent编排重构方案与外部工具借鉴讨论.md`。

> **结论先行：方案3 = 94.31%，比方案2（两通道仲裁 94.61%）低 0.30pp，逐卷全面略差。第三通道（场景块）是净负。**

## 一、方案做了什么

0935 的核心主张：**A/B/C 三个 pass 是三种正交 scaffold（信息结构不同，非采样），错误相关性低，所以三通道仲裁应优于两通道。**

在方案2（两通道仲裁，94.61%）基础上加第三通道：

| 通道 | 实现 | 单通道准确率 |
| --- | --- | ---: |
| A | `cont_agent`（逐条滚动，±8 行） | 92.31% |
| B | `evledger`（整卷 + 证据 + 账本） | 91.47% |
| **C（新增）** | **`scene_block`（场景块完整原文）** | **92.50%** |

实现：`annotator/arbiter3_agent.py`
- **三通道分歧检测**（纯代码）：三标签不全相同 → 五卷共 **999 条**（比两通道的 819 条多 **180 条**）
- 裁决器：`reasoning_effort=high`，输入**三个候选** + ±15 行原文 + 账本
- 合并：分歧用裁决，非分歧保持 cont

## 三、关键发现：为什么"更多通道"反而更差

### 3.1 量化归因（180 条新增分歧的性质）

第三通道把分歧集从 819 条扩到 999 条，新增的 180 条（`cont==ev ≠ scene`）性质如下：

| 类型 | 条数 | 性质 |
| --- | ---: | --- |
| cont/ev 对、scene 错 | **138** | **纯噪声**（把本来一致的正确答案拉进分歧集） |
| cont/ev 错、scene 对 | 25 | 有价值信号 |

**噪声是信号的 5.5 倍。**

三通道仲裁在这 180 条上的实际表现：

| | 条数 |
| --- | ---: |
| 改坏（原本 cont/ev 对 → 仲裁后错） | 22 |
| 修好（原本 cont/ev 错 → 仲裁后对） | 11 |
| **净** | **−11** |

### 3.2 机制解释

1. **第三通道质量不够**：场景块（C）自身 92.50%，且它**丢失了跨场景连续性**（见方案1报告）。它的错误与 A/B 不同源，但**错误率并不比 A/B 低多少**。
2. **噪声候选干扰裁决**：当三个候选不一致时，仲裁器看到 scene 的错误候选，有一部分条目被误导改坏（22 条），而 scene 正确带来的修复（11 条）不足以抵消。
3. **本质**：0935 的"正交 scaffold"假设只考虑了"错误相关性低"，**忽略了"新增通道的准确率必须足够高"**。低质量通道引入的分歧，是"把正确共识拆散"的破坏性操作。

### 3.3 对"信息增量公理"的边界补充（重要）

- 原公理（0932）：**任何有改写权的调用，必须拥有不同的信息来源。**
- **本方案补充**：**新增信息源不仅必须"不同源"，还必须"足够准"。** 否则它引入的噪声会超过信号，净负。
- 判据：新增通道的准确率若显著低于现有通道的**共识质量**，则不应加入仲裁集。

---

## 四、结论

1. **方案3（三通道仲裁）：94.31%，净 −0.30pp，不采用。**
2. **第三通道（场景块）净负**：180 条新增分歧中 138 条是噪声，仲裁净 −11 条。
3. **保留方案2 的两通道仲裁（94.61%）**，不加第三通道。
4. **可复用教训**：新增信号源要同时满足"不同源"**和**"足够准"两个条件；只有前者不够（本方案是反例）。
