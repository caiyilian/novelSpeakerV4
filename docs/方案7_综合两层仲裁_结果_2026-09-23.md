## 一、设计思路（为什么这样综合）

先量化了"方案2 与各方案的互补量"（"仅对方对"，即可被救回的条目）：

| 对比方案 | 互补量（可救回） |
| --- | ---: |
| **方案1 场景块** | **102（最多）** |
| evledger | 78 |
| 方案3 三通道 | 46 |
| 方案6 判据修正 | 32 |
| 方案5 精确契约 | 23 |
| 方案4 对抗裁决 | 18 |
| cont 基线 | 15 |

**深挖那 102 条"方案2错 / 场景块对"**：**86 条（84%）是实名互换**，集中在 v2（43 条，快速对话密集）。机制解释：场景块用「场景全文」能看到完整对话交替结构，而方案2 的 arbiter 只看 ±15 行 → 场景块正好补上"实名互换"这个盲区。

**但直接叠加失败**（方案3 已证：第三通道在 ±15 行下噪声 201 > 信号 102，净 −99）。

**所以方案7 的设计 = 两层仲裁**：
- **第一层**：方案2 的 arbiter（cont vs evledger 分歧，±15 行）→ 产出 `arb`
- **第二层**：**只对「arb vs scene 分歧」的 415 条**，用**场景全文**再仲裁（借方案1 的场景级视野）

实现：`annotator/final_arbiter.py`

## 三、关键发现：第二层净负（本轮最重要的负结论）

| 第二层效果 | 条数 |
| --- | ---: |
| 修好 | 33 |
| 改坏 | **39** |
| **净** | **−6** |

**逐卷**（修好/改坏）：v1 4/5、v2 8/8、v3 6/7、v4 9/10、v5 6/9 —— **全部为 0 或负**。

### 为什么"取长补短"的设计没有生效

我原推理：场景块能救回 102 条盲区 → 第二层应净正。实测失败的原因：

1. **第二层是"重新裁决"，不是"直接采纳场景块答案"**。它看到两个候选 + 场景全文后仍会独立判断，在 102 条里只救回 33 条。
2. **第二层同时改坏了 39 条**——415 条分歧里有大量"arb 对、scene 错"的噪声条目，第二层在这些条目上被误导。

### 深层结论（重要）

> **问题不在"通道选择"，而在"裁决器本身的能力上限"。**

同一个 `deepseek-v4-flash` 高推理裁决器，**无论给它 ±15 行还是整个场景，其准确率都不足以净正地改善已有的 93.65%**。这与方案3（三通道）、方案4（对抗裁决）、方案5（精确契约）的失败同源——**都是"v4-flash 在 12h 预算内的能力边界"**。

## 五、结论

1. **方案7（综合两层仲裁）：93.57%，净 −0.08pp，不采用。**
2. **第二层净 −6 条**：想用"场景全文"救方案2 的实名互换盲区，实际被噪声抵消。
3. **根本原因**：不是通道不够多、不是上下文不够长，而是**v4-flash 裁决器的能力上限**。
4. **最终结论**：**方案2（分歧仲裁）仍是唯一最优解（93.65%）**。在"只用 v4-flash + 单卷 12h 预算"的约束下，93.65% 是已验证的天花板。
5. **通往 95% 的路径**：用户已明确排除"放开模型"（12h 阈值内绝不用）。因此要么接受 93.65% 作为该约束下的最优，要么等待/验证模型换代。
