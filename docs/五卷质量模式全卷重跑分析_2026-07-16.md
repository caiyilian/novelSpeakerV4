# 五卷质量模式全卷重跑分析（2026-07-16）

## 1. 结论先行

本轮第 1 至第 5 卷均已完整跑完。五卷共有 7,009 条对话，`labeled.txt`、正式日志和参考答案数量全部一致，没有缺标或错位。

本轮使用高耗时 `quality` 路径，五卷累计消耗约 **4.72 亿 annotation tokens**，正式日志记录到 **102,955 次实际模型调用**，平均每条对话约 **14.69 次调用、67,389 tokens**。五卷并行后墙钟时间约 98 小时，符合本轮“不追求速度和 token，只追求质量”的实验设定。

但是结果没有达到预期：

- 五卷严格准确率：**86.30%**（6,049 / 7,009）。
- 五卷名称包含关系宽松准确率：**89.94%**（6,304 / 7,009）。
- 宽松口径仍有 **705 条错误**；达到 98% 最多只能留下约 140 条，还需要减少约 **565 条**。
- 相比紧邻上一轮备份，宽松准确率从 **84.35% 提升到 89.94%**，说明新的局部场景输入确实救回了不少旧错误。
- 但相比 2026-07-10 已经跑出过的五卷 **91.71%**，本轮反而下降 **1.77 个百分点**。
- 更关键的是，本轮日志中的旧 Labeler 基线单独可达到约 **90.60%**；经过昂贵的质量审计后降到 **89.94%**，审计层净改坏 **46 条**。

因此，本轮证明的不是“调用还不够多”，而是：**当前多 Agent 投票结构的证据并不独立，重复调用同一个模型会放大共同错误；部分裁决规则还会把更可靠的基线改坏。**

宽松口径只接受：

1. `A|B|C` 中任一参考候选；
2. 已命名人物的全名/简称字符串包含关系；
3. 规范化后的完全一致。

### 5.2 多数票不是独立证据

5 个局部 Agent 实际使用同一模型、同一份原文块和几乎完全相同的提示词，仅调用序号和 Key 不同。它们会高度相关地犯同一种错误。

- 局部面板总体宽松准确率约 87.60%。
- 当局部多数与基线冲突时，共有 1,233 条；局部多数命中 52.64%，基线命中 70.24%。
- 3 个终审总体约 87.71%。
- 当终审多数与基线冲突时，共有 641 条；终审多数命中 32.29%，基线命中 64.43%。

同一答案可能包含多个候选或全名/简称，因此两个条件命中率可能重叠；但相对强弱非常明确：**发生冲突时，基线远比审查多数可靠。**

`strong-local-panel-correction` 只要局部面板达到 4/5 就先于终审直接覆盖基线。实际有至少 32 条“基线正确、终审多数也支持基线”的样本，仍被局部面板改错。例如：

- 第 1 卷 #183：答案和基线均为 `赫萝`，局部票为 `赫萝/罗伦斯/罗伦斯/罗伦斯/罗伦斯`，三个终审全投 `赫萝`，最终却被规则改成 `罗伦斯`。
- 第 2 卷 #315：答案和基线均为 `罗伦斯`，三个终审也全投 `罗伦斯`，最终仍被局部多数改成 `赫萝`。

终审也不是真正独立。其输入会显示每个候选获得了多少局部支持，因此终审容易被局部多数锚定。增加 3 次终审调用没有形成三条新的证据链，而是在重复并放大先前判断。

### 5.3 邻居规则过度依赖交替假设

邻居 Agent 的任务是分别识别目标前一条和后一条对话。当前规则在“两侧邻居都等于基线，而局部 plurality 是另一人”时，把目标强制改成 plurality，相当于假设对话必然是 `A -> B -> A`。

但小说中同一人物可以连续说多句，两个相邻引号也可能只是排版拆句。典型反例：

- 第 1 卷 #540：答案和基线都是 `杰廉`，前后邻居审查也全部识别为 `杰廉`，规则却把目标改成 `罗伦斯`。
- 第 1 卷 #632：答案和基线都是 `罗伦斯`，前后邻居审查也全部识别为 `罗伦斯`，规则却根据“中间应换人”改成 `赫萝`。

该规则有 11 次救回、17 次改坏，净损失 6 条。问题不是代码写反，而是“夹心位置必然换人”的通用假设不成立。

## 6. 当前候选池的理论上限

705 个最终错误中：

- 216 条的基线原本正确，是审计层造成的错误；
- 489 条基线和最终都错误；
- 在这 489 条里，局部 plurality 正确 104 条，终审 plurality 正确 65 条；
- 允许从基线、5 个局部票和 3 个终审票中任意挑选时，有 218 条至少出现过一次正确候选；
- 仍有 **271 条没有任何一个说话人 Agent 提出正确答案**。

因此，即使存在一个知道答案的完美元裁判，从现有候选里选择的理论上限也只有：

`(7009 - 271) / 7009 = 96.13%`

这比 98% 仍低 1.87 个百分点。由此可以排除“只要再加一个更聪明的投票器就能到 98%”的设想。下一步必须提升**候选生成、整段场景建模和证据提取**，使正确答案先进入候选池。

## 9. 从日志确认的正确方向

### 9.1 应保留的部分

1. **正式日志与 temp 追踪机制有效。** 本轮可以完整追溯每个 Agent、模型 Key、输入摘要、票型、裁决来源、超时和失败轮。
2. **SenseNova 六 Key 轮询有效。** 调用分布均衡，失败后能切换并续跑，不需要调整模型优先级。
3. **非人物发声专门审查有正收益。** `audited-non-person` 100 次中正确 87 次，净救回 4 条，方向正确但仍需更严格证据。
4. **非法/空基线替换有必要。** 覆盖很小但净收益为正。
5. **原始场景块有价值。** 相比紧邻上一轮，五卷净修复 392 条，说明向模型提供局部原文和双侧叙事是正确基础。

### 9.2 已被数据否定的部分

1. **同提示词重复 5 次不等于 5 个独立 Agent。** 多数票会把同一系统性误读放大成高置信结论。
2. **不能仅凭 4/5 或 5/5 覆盖基线。** 在与基线冲突的选择性样本中，基线更可靠。
3. **终审不能看到局部支持票数。** 当前支持数会锚定终审，使其不再独立。
4. **不能把对话交替当硬规则。** 连续引号可能属于同一人物，`A-B-A` 只能是假设，不能成为覆盖证据。
5. **逐条只返回目标标签不够。** 提示词虽然要求先在脑中标完整块，但没有强制输出完整序列和每次换人的证据，模型可以跳过真正困难的中间推理。

## 10. 面向 98% 的下一步架构建议

下一版不应继续简单增加投票次数，而应改成“整段求解 + 证据对抗 + 全局复核”。建议顺序如下。

### 第一阶段：整段场景求解

1. 先按叙事边界把连续对话切成场景块，而不是每条对话独立处理。
2. 场景求解 Agent 必须输出该块**每一条对话的说话人表**，不能只返回目标行。
3. 每次说话人切换都必须附目标绑定证据：前置/后置说话动词、动作主体、称呼回应、明确自称或上下文排除。
4. 如果证据不足，Agent 应请求扩大原文范围，而不是用交替规律强行收敛。
5. 同一块的多条结果一次生成，使相邻句保持一致；之后再逐条写入状态和日志。

### 第二阶段：真正不同职责的 Agent

1. **结构证据 Agent**：只抽取引号边界、前后说话动词、动作主体和指代，不猜角色风格。
2. **场景序列 Agent**：基于结构证据给出完整 speaker sequence。
3. **反例 Agent**：接收两个候选及各自原始证据，专门寻找哪一个与原文直接矛盾。
4. **扩大上下文 Agent**：只在冲突未解决时读取更大范围、人物首次命名和动态别名证据。
5. **最终裁判**：只看原始证据和双方论证，不看票数，不知道哪个是基线，防止多数锚定。

这些 Agent 即使仍使用同一个 SenseNova 模型，也因为输入信息和任务不同而更接近真正独立的证据链。

### 第三阶段：保守覆盖与二次全卷复核

1. 默认保留基线；多数票本身不得触发覆盖。
2. 只有“目标绑定的直接证据”或“完整场景序列排除基线”才能改写基线。
3. 对所有基线/场景求解冲突运行扩大上下文，不限制 token 和调用次数。
4. 第一遍完成后按场景块进行第二遍全局一致性复核，重点检查：同一人物连续发言、无叙事分隔的引号拆句、多方谈判、主视角吸附、人物/非人物边界。
5. 动态学习全名、简称、身份称谓和无名角色描述，但只能从当前小说文本与证据库获得；**代码中继续禁止硬编码任何特定小说角色名、组织名或剧情规则。**

## 11. 最终判断

本轮不是完全失败：它显著超过紧邻上一版，证明局部原文块和可追溯审计是有价值的；但它也非常明确地否定了“同模型重复投票 + 支持数终审 + 对话交替纠错”这条路线。

目前最稳妥的判断是：

- 先撤销三类负收益覆盖规则，理论上可回到约 90.60%，但这只是止损；
- 仅优化元裁判也不可能达到 98%，因为当前候选池理论上限只有 96.13%；
- 真正的下一步必须让 Agent **显式输出和验证整段对话序列**，并在冲突时扩大上下文、比较原文证据，而不是继续堆同质票数。

这次长跑最大的价值，是把下一步方向从“再加 Agent”缩小成了更具体的结论：**增加不同证据链，减少同质投票；从逐句猜测转向整段场景求解。**
