## 4. 候选池上限

把每条对话的以下候选全部放进候选池：

1. 初始 Labeler；
2. 五张场景图；
3. 五个目标调查；
4. SceneEvidenceJudge；
5. ContrastiveBoundary；
6. 场景层结果；
7. SearchAgent/规范化后的最终结果。

人工答案在候选池中出现 6,818 次，理论上限为：

`6818 / 7009 = 97.27%`

初始 Labeler 的 637 条错误中，现有其他 Agent 只为 446 条提出过正确候选；另有 191 条没有任何 Agent 提出正确答案。即使存在一个知道答案的完美裁判，当前候选生成也达不到 98%。因此不能只调票数、阈值或裁判提示词，必须产生新的高质量候选。

## 5. 初始 Labeler 的错误结构

初始 Labeler 仍比任何二级 Agent 更可靠，但 90.91% 距离目标很远。637 条基线错误按类型分布如下：

| 类型 | 数量 |
| --- | ---: |
| 具名/具体人物 -> 另一个具名/具体人物 | 402 |
| 具名人物 -> 非人物发声 | 55 |
| 泛称 -> 具名人物 | 51 |
| 泛称 -> 另一个泛称 | 47 |
| 具名人物 -> 泛称 | 42 |
| 非人物发声 -> 具名人物 | 37 |
| 其他 | 3 |

真正主导误差的是人物身份互换，不是格式问题。最大的双向混淆仍是两个主要对话参与者之间的错位；类似问题也出现在其他多人场景、商谈场景和长段连续解释中。代码和提示词绝不能写入这些人物的名字，只能修复通用的引号作用域、话轮延续、后置归属和主视角吸附问题。

部分严格错误可能属于答案粒度差异，例如：

- 稳定泛称与带组织修饰的同义泛称；
- 参考答案保留角色身份，而输出使用后来证实的姓名；
- 同一无名人物的职业、外貌和场所称谓不同。

这些需要单独报告，但不能用来掩盖大量真实人物互换。第 1 至第 5 卷已经人工复核，本轮仍以现有答案为主标准；只有经原文身份链验证的同一人物，才可在语义指标中另计为正确。

## 6. 根因

### 6.1 初始提示词错误地扩大“附近发声动词”的作用域

当前 Labeler 明确写有“在目标附近五行发现发声动词就使用并结束”。这条规则没有先判断发声动词绑定前一个引号还是后一个引号，也没有处理一行多个引号、后置归属、冒号引出和连续拆句。模型会找到真实发声动词，却把它绑定到错误目标，因此大量错误仍自报 `explicit_attribution/high`。

`high|explicit_attribution|direct_speech` 虽然有 93.87% 准确率，但仍包含 242 条错误。模型自报的证据等级不能直接作为代码覆盖依据。

### 6.2 场景片段过短，完整场景名不副实

为避免结构化输出超过 4,096 token，当前每个场景最多 6 个对话轮次，原文只在首尾各补 6 行。许多真实话轮的锚点、参与者引入和延迟归属位于该范围之外。模型被要求输出“完整场景序列”，实际看到的却只是短切片。

### 6.3 同源模型的错误高度相关

五个 Mapper 和五个 Investigator 的职责名称不同，但它们仍在相同短上下文中推断同一目标。遇到作用域误读或主视角吸附时，多个 Agent 会一起犯错。4/5、5/5 和“多调查一致”只是重复同一错误，不能转换成高置信证据。

### 6.4 裁判任务比初始任务更弱

初始 Labeler 可以读取任意原文、搜索人物、看到运行时身份和短期上下文。许多二级 Agent 只看到短场景包或经过摘要的候选论证。它们的信息条件更差，却拥有覆盖更强基线的权力，导致系统性退化。

### 6.5 流式逐条提交缺少真正的全局复核

系统会缓存短场景图，但仍逐条最终写入。尚未实现“一个自然场景完成后，使用整段原文、全部初判和明确锚点进行第二遍联合求解并回写”。因此连续话轮的错误不能在看到后方锚点后整体修正。

## 7. 下一版改造

### 7.1 第一阶段：止损

1. 默认保留有效初始 Labeler。
2. 取消所有仅依靠场景票数、调查票数或对抗裁判一致性的改判。
3. 人物/非人物和直接归属只有通过确定性引号容器与作用域验证才可覆盖。
4. 保留 SearchAgent 的身份链，但改判必须记录可核查的原文桥接。
5. 所有被拒绝的建议继续写日志，作为离线候选而不是最终答案。

### 7.2 第二阶段：重做初始候选

1. Labeler 必须先列出目标附近全部引号及其作用域，再判断目标。
2. 非冒号的后置“某人说道”默认绑定前一个引号，不能跨到下一句。
3. 冒号引出的发声叙事只绑定其后引号。
4. 没有直接绑定时，分别从前方锚点正向重建、从后方锚点逆向重建。
5. 同一人物允许连续多句；任何换人都要说明称呼、问答、叙事动作或其他原文依据。
6. 运行时记忆只能提供待验证假设，不得充当原文证据。

### 7.3 第三阶段：扩大上下文但压缩输出

场景任务不再要求每条输出长篇理由。对更大的原文窗口，只返回：

- 对话 ID；
- 说话人；
- 证据类型；
- 锚点行；
- 很短的作用域说明。

借此把可见范围从 6 个轮次扩大到自然场景或重叠窗口，而不突破 4,096 输出上限。使用前向、居中、反向三个不同窗口形成真正不同的上下文视角，而不是同一窗口重复投票。

### 7.4 第四阶段：场景结束后二次联合复核

第一遍只产生 provisional 标签。自然场景结束后，第二遍输入：

1. 更大的完整原文场景；
2. 每条 provisional 标签；
3. 代码抽取的确定性前置/后置归属；
4. 所有冲突候选，但不展示票数；
5. 已验证身份链。

复核必须输出完整 speaker sequence 和每个换人边界。只有二次结果能解释全部直接锚点，才允许回写整段；否则只保留直接锚点和初始结果，并把冲突记为 unresolved。

### 7.5 离线验收

从本轮冻结日志建立四组回放样本：

1. 基线正确、后处理改坏的保护样本；
2. 基线错误、候选池已有正确候选的选择样本；
3. 基线和全部现有候选都错误的召回样本；
4. 与上述样本同场景、同长度的原本正确对照。

答案只在所有模型调用完成后用于评分，不进入任何提示词、消息、证据库或运行时状态。新模块接管默认输出前必须满足：

- 相对初始 Labeler 为正净收益；
- 基线正确保护率至少 99%；
- 候选召回理论上限超过 99%；
- 人物互换、人物/非人物和身份规范化三类均有跨卷正收益；
- 单元测试、40K 上下文检查和作品专有词扫描全部通过。

## 8. 通用性硬约束

这是通用小说对话角色标注项目。生产源码、系统提示词、正则规则、测试夹具和默认配置中，不得硬编码任何特定小说独有的：

- 角色姓名或别称；
- 组织、商行、地点、物种或道具名；
- 特定人物之间的交替关系；
- 某一卷的剧情、职业组合或场景规则。

允许使用的只有通用语言结构和运行时动态证据，例如引号位置、冒号、发声动词、问答关系、称呼、自我介绍、叙事身份桥接和当前小说证据库。正式运行前的源码扫描必须继续执行，发现作品专有词即报错。

## 9. 当前结论

本轮长跑给出了明确结论：增加调用和 token 本身不会提升准确率；在错误的证据结构上增加 Agent，反而会把相关性错误包装成一致结论。

下一版的核心不是“少调用”，而是把高成本用在新的信息视角上：更大的重叠原文窗口、正确的引号作用域、前后双向重建、身份链验证和场景结束后的联合复核。速度和消耗仍不作为目标，但任何额外调用都必须提高候选召回或保护正确基线，不能继续重复同一判断。

## 10. 本轮实现与 SenseNova 定点回放

### 10.1 已实现的止损与候选改造

本轮先把上一版代码独立提交并合并，再在新分支修改。当前实现包括：

1. 有效初始 Labeler 默认不再被普通场景票数、调查票数或对抗裁判覆盖；旧覆盖策略仅保留为显式测试兼容开关。
2. Labeler 改为先建立引号作用域账本，再从前后锚点双向重建；删除“附近五行发现发声动词即可结束”的错误规则。
3. 场景原文补边由 6 行扩大到 80 行，但仍受 40K 上下文预算保护。
4. 新增 `TargetBaselineFalsifier`，专门寻找初判之外的候选，但无直接改判权。
5. 从相邻场景话轮动态提取人物，强制加入匿名 A/B 对抗候选池，解决“所有目标 Agent 都没提出另一个在场人物”的候选缺失。
6. 主流程与场景层统一识别“搭腔、接话、回应”等通用发声动词，并排除“说不出话”等非发声结构。
7. 修复 `甲向乙搭腔`、`向乙搭腔的是甲`和长动作从句的主语/宾语抽取，所有名字均来自当前小说原文，不含作品专有常量。
8. 对“接话类后置归属被初判错误前移”增加三个专项复核。只有独立 Judge 与至少两个专项复核共同提出同一替代候选时才允许改判；否则保留初判并记录诊断。

### 10.2 定点回放结果

所有定点模型调用都只读取完整小说原文；参考答案在调用完成后才用于评分，没有复制进回放数据目录、提示词、工具结果、记忆或证据库。

| 类型 | 样本 | 结果 | 结论 |
| --- | --- | --- | --- |
| 保护样本 | 第 1 卷一个原本正确、旧场景层会尝试改坏的目标 | 初判与最终均正确 | 保守默认策略成功止损 |
| 无候选错误 | 第 2 卷第 668 条 | 相邻话轮机制成功把正确人物加入 A/B 候选池，但三个裁判仍一致选错，最终安全保留初判 | 候选召回提高，选择器仍不可靠 |
| 后置接话错误 | 第 3 卷第 313 条 | 发声动词同步后，多次回放能够召回正确候选；最终专项回放中前向专项正确、反向专项工具调用失败、对话行为专项错误、Judge 错误，故没有达到改判门槛 | 单一 SenseNova 在复杂互相致谢/交易角色语义上高度不稳定 |
| 正确对照 | 第 4 卷第 403 条 | 初判和最终均正确，窄门槛未误触发 | 当前保护条件没有在该对照上造成回归 |

第 2 卷回放尤其值得注意：三个裁判都在理由中使用了提示词明令禁止的职业、性格和话题风格推断。即使它们表面上“三票一致”，也仍是相关性错误，因而继续没有改判权。

第 3 卷最终专项回放共调用模型 31 次，耗时约 28 分钟，最终仍因证据不足保留错误初判。这不是速度或 token 不足，而是同一模型在该语义边界上的判断不稳定。继续机械增加同类投票不能证明能达到 98%。

### 10.3 对下一次五卷重跑的预期

根据冻结日志，初始 Labeler 为 90.91%，旧场景层把它降到 88.43%，最终身份处理回升到 88.84%。本轮首先取消了离线净收益为负的场景覆盖，因此合理预期是从 88.84% 明显回升并更接近初始 Labeler，而不是直接承诺 98%。

新提示词、作用域解析和候选补全可能继续带来正收益，但定点回放也已经证明：当前 SenseNova 仍会在复杂人物互换上形成高置信错误。下一次全卷结果必须继续按“初判、候选召回、Judge、专项复核、最终结果”分层统计，不能只看总准确率。若仍停留在 90% 至 94%，下一步应实现真正的全卷 provisional 标注后场景级第二遍联合回写，而不是恢复任何票数覆盖规则。
