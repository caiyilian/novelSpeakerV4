## 三、8 个方案详解

### 方案1：场景块标注（来源：0931 讨论文档）

- **思路**：用「自然场景的完整原文」替代 cont_agent 的「±8 行窄窗口」。每场景一个新会话（system + 账本 + 前情锚点 + 场景全文），场景内逐条标注。
- **实现**：`annotator/scene_block_agent.py`；复用旧系统 `scene_sequence.build_scene_segments`（max_turns=40），五卷切出 51-68 个场景/卷，18-26 条引语/场景。
- **结果**：**92.24%**（净 −0.94 vs 基线）
- **逐卷**：v1 94.96 / v2 92.49 / v3 95.06 / v4 89.69 / v5 89.86
- **失败原因**：为拿"场景内全局视野"，**牺牲了跨场景的滚动连续性**。v2 上大胜（+1.96），但 v4/v5 明显退化。
- **残留价值**：是**互补信号**——它能救回方案2 的 102 条盲区（其中 86 条是实名互换），这是方案7 的设计依据。
- **耗时**：单卷 7.5–9.5h（五卷并行实测；场景全文 prompt 大 20-30 倍）——**8 个方案里最慢，但仍 <12h**

### 方案2：分歧仲裁（来源：0932 讨论文档）

- **思路**：两个独立通道（A=cont_agent 逐条滚动；B=evledger 整卷+证据+账本）已各自存在。用**纯 Python** 找出两者标签不一致的条目（不碰答案），只把这些分歧交给一个**高推理裁决器**：它同时看到**两个候选答案 + ±15 行原文 + 角色账本**，独立判决。非分歧条目完全保持 cont 不变。
- **实现**：`annotator/arbiter_agent.py`
- **规模**：五卷分歧 **819 条** → 簇化 **361 簇**
- **结果**：**94.45%（修正后）** / 93.65%（初版有 bug）；正确 6620/7009
- **逐卷**：v1 96.37 / v2 92.42 / v3 96.95 / v4 93.15 / v5 93.97
- **为什么有效**：裁决器拿到的是**两个不同上下文产生的判断**——这个信息任何单通道都没有（0932 的"信息增量公理"）。且只改 11.7% 的条目，保护其余 6190 条正确项。
- **盲区（外部复核指出）**：仍有 **227 条** cont 与 evledger 给出**相同标签但都错**——分歧检测器**根本不触发**，仲裁无从介入。
- **耗时**：8.0 分钟（五卷并行；逐卷 132–481s）

### 方案3：三通道仲裁（来源：0935 讨论文档）

- **思路**：在方案2 基础上加**第三通道**（场景块），三通道分歧裁决。
- **实现**：`annotator/arbiter3_agent.py`
- **结果**：**93.58%**（净 −0.07 vs 方案2）
- **失败原因（已量化）**：第三通道引入的 180 条新增分歧里，**138 条是纯噪声**（cont/ev 对、scene 错），只有 **25 条真信号**——噪声是信号的 5.5 倍。仲裁净 −11 条。
- **关键教训**：**新增信号源必须同时满足「不同源」和「足够准」**。0935 只考虑了前者。

### 方案4：对抗裁决 Refuter（来源：0936 讨论文档）

- **思路**：裁决机制从"选哪个对"改成"**找出哪个候选与原文矛盾**"（行号级反证），窗口放宽到 ±30 行。
- **实现**：`annotator/refuter_agent.py`
- **结果**：**92.60%**（净 −1.05 vs 方案2）
- **逐卷**：v1 96.15 / v2 90.04 / v3 96.95 / v4 90.26 / v5 90.68
- **关键发现**：与方案2 **高度互补**——819 条分歧里 **143 条"仅一方对"**（仅方案2 对 78、仅方案4 对 65）。但 v2 上明显劣于方案2（−2.03）：快速对话交替需要**整体理解**，而非行级反证。

### 方案5：精确契约 + 证据强制（来源：09-46 讨论文档）

- **思路**：① 用 `quote_occurrence` 的精确 span + 同句序号 + scope 定位引语；② 裁决器**必须**输出证据行号且在原文范围内，否则拒绝该条裁决；③ parse 从子串匹配改精确匹配。
- **实现**：`annotator/arbiter5_agent.py`
- **结果**：**92.85%**（净 −0.80 vs 方案2）
- **结论**：**精确契约是"工程健壮性"改进，不是"涨分"机制**。证据强制拒绝了部分原本有效的裁决。价值在于可审计、可复现，应进生产系统但不指望涨分。

### 方案6：无人称引语判据修正（来源：1015 讨论文档）

- **思路**：1015 发现最大错误块是"无人称引语过判"（236 条），根因是判据错位（引号类型 vs 可归属）。只对 cont 判为"无人称引语"的条目，用**可归属**判据二次确认。
- **实现**：`annotator/np_refine_agent.py`
- **结果**：**92.27%**（净 −1.38 vs 方案2）
- **逐卷**：v1 94.81 / v2 88.07 / v3 95.8 / v4 91.48 / v5 91.91
- **关键**：修订后改判数从 358 降到 194（−46%）——因为 cont 用了新提示词后自己就处理了大部分过判。**这印证了"改提示词比事后补救更根本"**，也是本轮把判据修进提示词的直接依据。

### 方案7：综合两层仲裁（用户要求的"真正综合方案"）

- **思路**：先量化互补量 → **方案1 场景块能救回方案2 的 102 条（最多）**，其中 86 条是实名互换（集中 v2）。机制：场景块用场景全文看完整交替结构，方案2 arbiter 只看 ±15 行。于是设计**两层仲裁**：
  - **第一层**：方案2 的 arbiter（cont vs evledger 分歧，±15 行）
  - **第二层**：**只对「arb vs scene 分歧」的 415 条**，用**场景全文**再仲裁
- **实现**：`annotator/final_arbiter.py`
- **结果**：**94.65%（修正后，排名第 1）** / 93.57%（初版有 bug）；正确 6634/7009
- **逐卷**：v1 96.59 / v2 92.91 / v3 97.12 / v4 93.21 / v5 94.04
- **失败原因（已量化）**：第二层**修好 33 条、改坏 39 条，净 −6**。原因：第二层是"**重新裁决**"而非"直接采纳场景块答案"，102 条只救回 33；同时被 415 条分歧里的噪声（arb 对、scene 错）误导改坏 39。
- **外部复核补充**：方案7 **只重审 `arb != scene` 的条目**，同样**没有覆盖 227 条共识盲区**。所以"扩大仲裁窗口失败" ≠ "编排已到上限"。
- **耗时**：13.5 分钟（五卷并行；逐卷 256–722s）

### 附：evledger（整卷通道，非"方案"但被反复引用）

- **思路**：把整卷小说全文 + 全部引语清单一次性给模型，要求输出 `编号|说话人|证据行号|依据` 四元组。
- **实现**：`annotator/evidence_annotate.py`
- **结果**：**92.65%**（+1.35）
- **本轮唯一上涨的方案**（修订前 91.47 → 修订后 92.65，+1.18）：它原提示词把"神态字幕"明确列入触发清单、错得最多，改判据后受益最大。

## 三、三条被数据验证的核心教训

1. **分歧仲裁 = 真实信息增量**（两个不同上下文产生的判断），这是唯一稳定有效的机制；而"同源投票 / 低质量第三信号"净负（方案3 实测：180 条新增分歧里 138 条是噪声）。
2. **新增信号源要同时满足「不同源」和「足够准」**——只有前者不够（方案3 是反例）。
3. **改提示词判据比事后补救更根本**（方案6 的改判数在提示词修正后骤降 46%），但**判据本身必须正确**——"引号类型"判据是错的，"可归属"判据才对。

### 4.0.1 关于"12h 阈值"的诚实说明

**触发"放开模型"的条件是单卷标注 >12h。这个条件从未真正满足：**

| 场景 | 单卷用时 | 是否 <12h |
| --- | ---: | :---: |
| 五卷并行（5 任务，正常调度） | **3.2–3.8h** | ✅ 远低于 |
| 五卷并行 + 另一批五卷同时跑（10 任务） | 13.1–13.5h | ❌ |

**修订后那轮 cont 基线测到 13.46h，是我的调度失误造成的**——我把 cont 五卷和 scene 五卷（共 10 个任务）同时启动，20 个模型账号被 10 路分摊，导致每路速度降到约 1/3.5。同一脚本在**正常五卷并行**下（修订前那轮）单卷仅 3.2–3.8h。

**所以：单卷真实用时约 3.2–3.8h，从未接近 12h 阈值，"放开模型"的前置条件不成立。**

| ~~"v4-flash 在 12h 内能力上限 93.65%"~~ | **不成立**（见 6.2） | 推断链缺失 |

### 6.2 为什么"能力上限"的推断不成立

初版的推理是"8 个方案都失败 → 所以是模型能力上限"。**这个推理缺少关键环节**：

1. **失败的原因不是"能力不够"，而是"覆盖不到"**：方案2 的 227 条错误是 **cont 与 evledger 给出相同标签但都错**——分歧检测器**根本不触发**。方案3/4/5/7 都建立在"分歧"之上，因此**都无法触及这 227 条**。这不是能力上限，是**机制盲区**。
2. **剩余错误混合四种不同成因**（说话人归属 / 角色身份表示 / 局部标签写法 / 评分口径），把它们统计成"模型识别失败"会严重误导。
3. **已实测存在可修复路径**：外部复核用"原文驱动的场景角色表"做了定向原型，在**答案不进入模型请求**的前提下，把方案2 从 6620 提升到 **6734/7009 = 96.08%**，**五卷每卷都 >95%**。

### 6.3 定向原型的结果与它的边界（诚实标注）

| 实验 | 目标 | 净修复 | 耗时 |
| --- | --- | ---: | ---: |
| 第4卷整段**开放式**重标 | 34 条"村民" | **+4**（称谓碎裂） | 45.9s |
| 第4卷**封闭角色表** | 同 34 条 | **+33 / −0** | 21.4s |
| 第2卷商行三人场景 | 23 条 | **+23 / −0** | 12.6s |
| 第4卷高推理（8192） | 同 34 条 | **0 条可解析**（`finish_reason=length`，推理耗尽） | 63.3s |
| 表面写法规则（无模型） | "叶克伯/叶克柏" ±90 行 | **+30 / −0** | — |
| 表面写法规则（无模型） | "女服务生/酒吧女孩" ±150 行 | **+30 / −2** | — |

**合并后**：6620 → **6734/7009 = 96.08%**（五卷百分数简单平均 96.12%）。

> ⚠️ **这不是生产成绩**（外部复核已自行声明，我认同）：
> - 规则是在**看过这五卷错误之后**设计的 → **开发集选择偏差**；
> - 窗口（±90/±150）与词对（叶克伯/酒吧女孩）是**针对性设定**，不可硬编码为"通用算法"；
> - **未做未见卷盲测**，未做端到端完整运行。
>
> 但它**足以反驳"八方案全失败所以模型无法达到 95%"这个推断**，并指出下一步该做什么。

### 6.4 真正的下一步（外部复核建议 + 我认同）

核心不是"再叠一层泛化裁决"，而是**加入可核验的场景实体层**：

1. **修正评分一致性**（双侧归一 + 唯一冻结证据库 + 冻结哈希）——**这是前提，必须先做**。
2. **实现通用的**场景实体表 / 证据 span / 显示标签作用域 / **共识风险触发器**（覆盖 227 条盲区）。
3. 用第 2、4、5 卷现有误差做开发，但**只用原文 + 旧预测**作为运行输入（不喂答案）。
4. 保留第 1、3 卷做**回退哨兵**；另选**未参与设计的卷或锁定盲审片段**，先跑完整候选再一次性开封评分。
5. 做**逐组件消融**：方案2 → +评分修正 → +实体表 → +局部显示标签 → +共识风险审查 → +回写约束，记净修好/改坏。

**验收标准**：**新口径 + 盲测 + 端到端 <12h** 三者同时成立，才可宣称稳定达到 95%。

### 6.5 待裁定的口径问题（外部复核提出，需要你决定）

- **同一角色是否全卷统一标签？** 若要求统一，评分器应给同一实体的已核实别名统一记分；若要求"每处用当时原文称谓"，提示词与记忆层必须允许按场景改变显示标签。**当前提示词要求全卷统一，但部分答案随段落改变**——这是口径矛盾，必须先裁定。
- 例如第 5 卷"女服务生 / 酒吧女孩"：同一身份两种标签，**不能统计成 30 次人物识别失败**。

## 八、我的自查

**这次错误的责任在我**：

1. 我在 §4.1 明知"修订后答案改用「无人称引语」"（我自己改的），却**没有同步检查 `cont_agent.semantic` 的映射方向**——它只映射输出侧。这是**改答案时漏改评分器**的连锁失误。
2. 我在最终结论里把"8 方案都失败"直接推成"模型能力上限"，**跳过了"失败原因是否同类"的检查**。外部复核用 227 条共识盲区证伪了这一步。
3. 教训：**改动评测口径时，评分器必须同步审计**；**"某机制无效"不等于"问题无解"**——要区分"机制覆盖不到"与"能力做不到"。
