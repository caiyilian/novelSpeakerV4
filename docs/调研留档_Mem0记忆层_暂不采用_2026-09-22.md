# 调研留档：Mem0 记忆层（暂不采用）

记录日期：2026-09-22。结论：**内容基本已被本项目前期调研覆盖，不引入；但"时间维度"一点值得注意。**

来源：微信文章《Mem0：AI 记忆界的顶流，凭什么这么火》（2026-08-27）+ `github.com/mem0ai/mem0`。

---

## 一、Mem0 是什么

**通用记忆层**（Universal memory layer for AI Agents）——给 AI 装一个跨会话、跨应用的"记事本"。三层记忆各管一摊：用户层（偏好）、会话层（聊到哪）、Agent 层（学会了什么）。

**2026-04 算法换代**（本文重点）：

| 旧方案 | 新方案 |
| --- | --- |
| 抽取事实 → 向量库 → 相似度检索 | **一次性写入、只增不改**（1 次 LLM 调用） |
| 孤立碎片 | **实体抽取 + 建关联**（人/项目/时间点连成网） |
| 只靠相似度 | **语义 + 关键词 + 实体信号一起打分** |
| 不区分时间 | **时间单独处理**（分清现在/过去/将来） |

效果（官方基准，**云平台数据**）：LoCoMo 71.4 → 92.5，LongMemEval 67.8 → 94.4。

## 三、唯一可参考的点：时间维度

Mem0 新算法特别强调"**对时间单独处理**"——检索时能分清"未来那个周二" vs "上次提到的某个周二"。

**这恰好命中本项目最难的"前向引用"问题**：

> 某处引语的说话人，取决于"该角色**此刻**是否已揭示身份"。例：某个称呼在第 222 行揭示是「赫萝」，那么第 100 行的该称呼应标什么？

本项目的现有解法是"账本 + 揭示行回填"（**静态**），但**没有实现"双时态账本"**——即每个别名带 `valid_from_line` / `valid_to_line`（"这个称呼在哪个行区间有效"）。

- 1015 报告 §3.7 建议过这个设计（借鉴 Graphiti 的 `valid_at` / `invalid_at` 双时态失效）；
- 六方案**均未实现**；
- 如果重跑后 v4/v5 的"实名互换 / 前向引用"仍是主要瓶颈，这是**下一个值得试的方向**（比"再加一层审裁"更有理论依据）。

---

## 四、结论

1. **不引入 Mem0**：它是通用记忆层 + 需另配 LLM + 主打云平台/跨应用，而本项目是**单卷批处理**，这些特性用不上。
2. **机制已覆盖**，无新增可借鉴项。
3. **唯一可参考**：其"时间维度"处理 → 提示本项目"**双时态账本**"（带有效行区间）是尚未实现的方向，待验证。

> 一句话：这篇文章对本项目是"印证"而非"增量"——它证明了"记忆要按时间分层"这个方向，而这正是我们还没做的那一块。
