记录日期：2026-09-22。分支 `feat/scheme-4-refuter`。方案来源：`docs/discussion/20260921_0936_agent编排方案调研与设计.md`。

> **结论先行：方案4 = 94.42%，比方案2（独立判断 94.61%）低 0.19pp，近似打平。但两者高度互补（143 条"仅一方对"），"对抗裁决"值得作为方案2 的补充机制保留。**

## 一、方案做了什么

0936 的独特裁决机制是 **Refuter（对抗裁决）**：不问模型"选哪个对"，而问"**找出哪个候选与原文矛盾**"（行号级反证）。0936 主张这比开放式的"选边"更聚焦。

实现：`annotator/refuter_agent.py`
- 分歧检测：同方案2（cont vs evledger，819 条），纯代码
- 裁决器：`reasoning_effort=high`，**±30 行更宽窗口**（vs 方案2 的 ±15）
- prompt：要求"找出与原文矛盾的候选"——若 A 有反证选 B，B 有反证选 A，都无反证则保守保留 A
- 输出：`D编号|最终说话人|反证行号|依据`

**与方案2 的唯一差异 = 裁决机制**（找反证 vs 独立判断），其余完全相同。

## 三、关键发现：两种裁决机制高度互补

在 819 条分歧上，方案2（独立判断）与方案4（对抗裁决）的四象限：

| 情形 | 条数 |
| --- | ---: |
| 两者都对 | 510 |
| **仅方案2 对** | **78** |
| **仅方案4 对** | **65** |
| 两者都错 | 166 |
| **互补总量（仅一方对）** | **143** |

**143 条里只有一方能对**——说明两种机制捕获的是**不同的正确信号**：

- **方案2（独立判断）擅长**：v2 这类"快速对话密集、需整体理解交替结构"的场景（+1.75pp）。开放式判断让模型可以整体把握对话流。
- **方案4（对抗裁决）擅长**：v1/v4 这类"有明确原文反证"的场景（+0.15/+0.71pp）。聚焦的"找矛盾"任务在反证明确时更准。
- **v2 的反例**：快速对话交替的歧义往往**不是"明确矛盾"**，而是"需要理解整体交替"，此时"找反证"的聚焦视角反而丢失了整体判断（−1.75pp）。

## 四、结论

1. **方案4（对抗裁决）：94.42%，净 −0.19pp，不单独采用。**
2. **与方案2 近似打平**（−0.19pp），但逐卷各有胜负。
3. **两者高度互补**：819 条分歧里 143 条"仅一方对"——这是综合方案的直接素材。
4. **建议**：把"对抗裁决"作为方案2 的**补充信号**（例如两者结果不一致时，再引入第三层判断），而非替代。但要先验证第三层能否可靠地在 143 条上选对（避免重演方案3 的"低质量第三信号"陷阱）。
