# 重构前复盘：历次全卷结果、架构演变与调研计划

记录日期：2026-09-20。源码基准：`077831ebd2d8fcba46c4cedf8b9b4411b06f68a2`，桌面版 v1.0.4。

本文用于交接下一阶段重构。它汇总仓库内既有分析、提交历史和本地实验存档，不是新一轮模型评测，也不是外部项目调研报告。本次只新增本文，不修改程序、提示词、模型配置或标注产物，不恢复运行，不发起模型请求。

公开版本已脱敏：不包含个人配置内容、配置文件绝对路径、账号数量及归属、密钥、服务地址、端口或私有网络信息。运行产物继续保存在本地，不随本文上传。

## 1. 用户此次暂停的原因与决定

### 1.1 原意记录

用户已经停止五卷任务并完成备份，希望先停止沿旧路线继续叠加功能，再重新审视项目。主要判断如下：

1. 最近几次更新的准确率收益有限，标注时间却越来越长，且常常不是小幅变慢。
2. SenseNova Flash Lite 的响应速度、TPM/RPM 约束和网络波动会影响耗时，但用户认为更关键的问题是项目臃肿、没有抓住核心困难。
3. 项目自研了大量 Agent 编排、记忆、工具调用、审阅、裁决、重试与状态管理，单人维护压力越来越大，存在重复造轮子的嫌疑。
4. 值得对照的不只是假定存在的“小说标注开源项目”，更包括通用 Agent 工具与基础设施。用户举出的对象包括 WorkBuddy、Codex、OpenCode、CodeWhale-TUI 等。
5. 用户提出一个待验证假设：成熟 Agent 工具接入较强的 DeepSeek 模型，利用其现成的任务执行与多 Agent 能力，可能比当前系统更准确，也可能更快。
6. 这不是要求把速度、低成本放到准确率之前。用户仍然愿意为真实的质量提升花几天时间和大量 token；不能接受的是成本持续增长，却缺乏相称的质量收益。
7. 当前只要求记录、汇总和提交文档，不要求马上改代码，也不要求马上开展外部调研。

以上第 2、3、5 点包含用户的判断或假设。历史数据支持“部分额外审阅负收益或低收益”，但尚不能证明所有耗时都来自架构，也不能证明某个外部工具必然更准。后续必须做同数据、同模型、同评分口径的对照。

### 1.2 下一阶段模型方向

后续计划以 **DeepSeek V4 Flash 替换 SenseNova Flash Lite** 作为主要实验模型，通过统一模型接入层使用。用户表示可用调用资源充足，因此下一阶段不应为节省 token 而过早压缩模型能力。

这是已记录的方向，不代表本次已完成模型切换、连通性测试、能力验证或配额核验。实际模型标识、工具协议、上下文和输出限制，留待实施阶段核验。公开文档只保留模型替换决定，不记录个人模型池配置。

### 1.3 不变的质量约束

- 目标是前五卷**每一卷**准确率超过 98%，接近 100%，不只是加权平均超过 98%。
- 这是通用小说对话角色标注系统，不能在生产代码、提示词模板、默认配置或规则中硬编码特定作品的人名、组织、场景或剧情关系。
- 角色有经原文证明的名字时，必须优先输出名字；“姓名”与“头衔加姓名”可以等价，“姓名”退化成职业或外貌泛称不能自动算对。
- 没有名字的路人可以使用来源明确的泛称。两个泛称是否同一人应由文本证据决定，不能靠针对某部小说的词表强行合并。
- 参考答案只用于离线评分，不进入标注模型输入、工具结果、记忆或证据库。
- 不承诺单靠更强模型或某个框架就能达到 98%。

## 2. 如何阅读历史数据

### 2.1 证据范围

本次梳理了十余个全卷结果阶段，另列小样本、答案修订与最新停跑快照。主要依据是现有 Markdown 报告、备份目录、本地分析 JSON 和 Git 提交，不是凭对话中的印象补数字。

日期通常是**结果分析或存档日期**，不一定是开跑日期。若代码在长跑结束后才提交，提交 SHA 表示该实现的归档位置，不保证每个续跑进程都使用该 SHA 的精确内容。不能把提交时间简单当成实验切换时间。

### 2.2 四种口径不能混用

| 口径 | 含义 | 主要限制 |
| --- | --- | --- |
| 严格字符串 | 输出命中 `A|B|C` 参考候选之一 | 全名、简称、同义泛称会造成虚低 |
| 当时宽松口径 | 规范化非人物标签、姓名包含等 | 不同阶段规则仍有变化，不是完整身份真值 |
| 已验证别名/语义口径 | 再使用证据库中的身份关系及方向性规则 | 别名库也是系统产物，必须防止循环验证和跨轮评分漂移 |
| 人工复核后重算 | 保持同一输出，替换修订后的答案再评分 | 不是一次新标注，更不能归功于代码升级 |

姓名包含、别名和泛称规则的接受范围并非一直相同。本文保留原报告口径；只有原报告明确用同一验证器重算过的对照，才按同口径解释变化。

### 2.3 数据集变迁

当前主评估集为第 1 至第 5 卷，共 **7009 条**：1349、1425、1215、1561、1459 条。第 1 卷人工校对最充分；第 2 至第 5 卷在 7 月初完成针对高亮差异的人工复核，但仍可能存在边界争议，不能声称绝对无误。

- 第 6 卷：早期输入/参考答案错放，后来确认缺少真正第 6 卷的可用参考答案，退出评估。
- 第 7 卷：短篇、心理与非人物内容占比不同，用户决定不再作为主要测试卷；不能把其退出造成的平均分变化当成系统提升。
- 第 8 卷：曾加入六卷评估，但参考答案未经人工复核，后来退出主要验收。不能和前五卷平均分直接比较。

## 4. 各阶段做了什么、发现了什么

### 4.1 早期本地模型与记忆架构

早期结构是 Python/Boss 逐句调度 Labeler，配合短期记忆、长期压缩、角色状态及后来的 FactCurator。v2.1 全卷报告显示工具调用率 93.0%、总 token 约 2137 万，但准确率只有 50.11%。主要问题是提示词规则互相矛盾、非人物发声滥用、角色状态污染、压缩幻觉及连续说话人错位。

改动包括重写提示词、弱化/停用不可靠长记忆、去除带旧标签的导航干扰、增加事实整理、清理角色名污染。后续英文提示词重写、EvidenceVault 与 SearchAgent、短记忆锚点也陆续进入主线，相关归档为 `7ff527a`、`aa75163`、`f4b08af`、`0d5fef4`。

必须区分：v3 的 83% 是 **100 条测试**，不是全卷 83%。旧报告中针对 Qwen3:32B 的“约 67% 上限”等判断是当时推测，不是经过证明的能力上限，不能带入下一阶段作为事实。

仓库早在 6 月已有《v2.1 vs opencode 对比分析》，记录过批量阅读、简洁提示、轻量身份表与复杂记忆流程的对比，并转述约 90% 的外部流程结果。但缺少统一数据快照与可复现控制条件，不能当作今天已完成的公平竞品测试。值得回看的是比较思路，不是照搬旧分数。

### 4.2 API fallback：先解决能否跑完

归档 `fcd7ca1`、`f280c54`。新增兼容 API 路径、模型可用性与工具调用检查、优先级、请求间隔、冷却、工具参数兼容、调用来源记录和作品专名扫描。

当时为了将来适配本地小模型，曾统一限制为 40K；还限制读取行数、工具输出和历史工具响应，防止一次审查堆出超大上下文。第 1 卷达到 93.8%，但末段明显较弱：第 1001 至 1100 条只有 84%，第 1201 至 1300 条 88%。只看前 100 条会漏掉主要问题。

随后引入通用 Risk Detector/Verifier：识别多人物、短句、泛称、引用与轮次风险，必要时复核。用户明确拒绝针对某一部小说的组织、追兵等场景写专用归一规则。主要应解决真实人物互换，而不是只把所有字符串差异做成规则。

### 4.3 多卷并行、验证修复与参考答案清理

归档 `38b864b`、`e6b51d2`。引入独立数据目录、不同优先级、单模型选择、模型池、断点续跑及逐次调用临时日志。单模型超时、`no tool call`、工具 JSON 缺逗号、代理连接失败、上下文累计超限等都暴露过真实运行问题。

验证器曾只读取一行的第一个答案标记，多引号/多标记会漏项和错位，后来修复为逐个解析；续跑指标也必须针对完整产物重新计算，而不是拿本次进程计数代表全卷。新增全部错误输出和独立 `answers_review.txt` 高亮，不覆盖原始答案，支持人工核查。

### 4.4 7 月 5 日：答案问题先于架构结论

六卷严格 83.81%、宽松 87.09%，严格差异 1325 条。报告中人物/群体互换 502 条、人物被判为非人物 190 条，此外混有答案泛称、缺候选和全名/简称差异。

完成差异高亮人工复核后，前五卷同一批输出的严格分数大幅上升。这说明早期某些低分不能全算在模型头上，也说明参考答案必须版本化。仅修改答案得到的提升，不是算法进步。

归档 `b568934` 增强对话结构提示、风险复核、修正应用及人工高亮工具。后续全卷才检验这些代码是否有效。

### 4.5 7 月 7 日：结构风险复核未产生稳定收益

前五卷宽松 92.77%，六卷宽松 91.46%。与人工复核后旧输出相比，前五卷严格分数全部下降，尤其第 5 卷下降约 4.39pp。

六卷 RiskVerifier 确认 3489 次、不同意 215 次，实际应用修正 144 次。第 8 卷 24 次修正中只有 4 次修正后正确，另外 20 次仍错或发生回归。高置信 `explicit_attribution` 会误绑定附近人物，`alternation` 会把叙事打断或同人连续发言误作换人。

后续方向是减少弱证据自动改写，统一非人物标签、强化动态姓名归一，增加轮询和故障恢复。轮询解决请求分配与可用性，不创造模型多样性，也不直接增加单次判断能力。

### 4.6 7 月 10 日：轮询稳定，但人物归属仍是瓶颈

归档 `39936fc`。六卷宽松 90.52%，前五卷 91.71%。第 3 卷严格仅 58.77%，宽松却为 93.00%，主要是完整姓名与简称差异。这是必须保留双指标的典型例子。

六卷 753 条宽松残余错误中，已命名人物错配/场景混淆 387 条、泛称到具体名 101 条、无关标签或问号 94 条、人物误判非人物 82 条、反向 50 条、实名降级泛称 39 条。两位核心人物互换 155 条，只占问题的一部分，不能把所有错误简化为某两个人的专用规则。

正式调用来源显示轮询均衡；主要问题是原文归属证据不足、问答/叙述关系误读和输出规范不稳定，而不是某个接入身份拖垮整卷。

### 4.7 对话块盲审实验与 7 月 12 日低谷

归档 `c8878e6`、`3d09d7b`。新增 QuoteTypeAgent、LocalAttributor、BlockSolver、CounterfactualReviewer、CitationArbiter，原文证据包不带旧标签，前三个判断互相不可见；确认锚点与暂定记忆分开，增加结构化提交和恢复。

这套设计试图降低基线锚定，改成小块联合推断。但下一轮报告保存的紧邻备份只有前五卷 84.35%，明显低于 91.71%。该阶段没有独立完整诊断报告，本文只保留可确认的结果和设计，不声称已精确分离每个 Agent 的因果影响。

需要保留的教训是：职责名称变多、宣称盲审、切换成块处理，都不能代替跨卷收益测量。

### 4.8 7 月 16 日：昂贵审计反而净改坏

归档 `2c92810`，PR #28。前五卷 89.94%，相较低谷修复 615 条、回归 223 条，净增 392；但相较 7 月 10 日修复 230、回归 354，净少 124。

本轮约 **4.72 亿 annotation tokens、102955 次实际模型调用、并行墙钟约 98 小时**；平均每条约 14.69 次调用。初始 Labeler 单独正确 6350/7009=90.60%，质量审计救回 170 条、改坏 216 条，最终 6304/7009=89.94%，净损失 46 条。

日志揭示的具体机制：

- 5 个局部判断使用同一模型、相近提示和相同原文，错误高度相关。
- 强局部多数可在终审仍支持正确基线时覆盖它。
- 终审看到局部支持数，发生多数锚定。
- “前后同人则中间应该换人”的邻居规则净收益为负，小说不满足机械 `A-B-A`。
- 271 条错误没有任何候选正确，现有候选池理想上限只有 96.13%，仅换投票器达不到 98%。

这轮已经否定“继续同质投票就会稳”的假设。其价值在于可追溯日志让负收益暴露，而不是高 token 消耗本身。

### 4.9 7 月 26 日：整段场景与对抗层仍然改坏基线

归档 `4926c1d`，PR #30。实现稳定场景块、五个完整场景 Mapper、五类目标 Investigator、无票数 Judge、候选 A/B 简报、镜像边界裁判、反事实复核、身份搜索和缓存。

理论上是“多种证据链”；实际上全卷结果降到 88.84%。分层准确率为：初始 Labeler **90.91%**，整段场景/对抗层 **88.43%**，身份搜索后 **88.84%**。场景层救回 190、改坏 364，净损失 **174**；身份层净增 29。

主要原因是：

- 场景为了结构化输出稳定，常被收紧到最多 6 个对话，早期补边仅 6 行，并不是真正自然场景。
- “附近五行发现说话动词即可结束”会把真实归因绑定到错误引号。
- 二级审阅器的信息反而比可主动查原文的 Labeler 少，却拥有改写权。
- 模型自报 `direct/high` 不保证引用真正绑定目标。
- 各审阅器在与基线冲突时都不如基线可靠，完美选择现有候选也只有 97.27%。

后续 `69c2bc1`（PR #31）改为默认保护有效基线、删除附近发声动词即停规则、扩大补边、加入反证与动态候选、修正通用后置归属作用域，并增强模型池冷却恢复。

定点测试也给过警告：10 条混合集曾为 10/10，但扩大到 25 条旧错误时最终仅 11/25；另一个难例约 31 次调用、28 分钟仍未解决。小样本命中不能证明全卷成功。

### 4.10 8 月 3 日：止损有效，旧审计成本却大量保留

宽松从 88.84% 回升到 92.21%，当时已验证别名口径 92.75%。旧报告逐条比较修复 440、回归 204、持续错 342。最显著错误仍是两位核心人物互换，共 122 条，以及引号连续拆句、人物/非人物、身份归一。

但 6987/7009 条决策保留了基线；基线错后改对仅 8 条，基线对后改错 3 条。正确样本平均约 16.47 次调用，错误样本约 17.97 次。调用层保留下来了，决策权收紧后却几乎不再提供增益。

后续新增精确引号实例账本 `quote_occurrence.py`：对话 ID、同一行第几个引号、字符区间与前后叙述；清理伪归因；新增真正首遍结束后的 `volume_review.py`，保存 first-pass 快照，整卷复审完成才发布最终结果。归档 `1ee8cfc`。

### 4.11 8 月 15 日：全卷第二遍有收益，但很薄

同验证器旧结果 92.85%，本轮首遍 93.12%，最终 93.29%。第二遍 166 次改写，修复 76、回归 64、语义中性 26，净增 **12 条**。第 4 卷复审净减 1 条，第 5 卷净减 18 条。

470 条剩余错误中：实名互换 242、泛称不一致 62、人物误判非人物 52、泛称误判实名 45、实名降级泛称 37、非人物误判人物 32。第 4、5 卷占全部错误 61.7%。

主要问题变成“一致票仍然会错”与“复审错误覆盖”。于是继续增加实名保护、独立发声类型任务、更多证据视角、镜像稳定性门槛、重试和进度显示。再次强调，修复验证虚低也不能把 93% 自动变成 98%。

### 4.12 9 月 1 日：原生 256K 有进步，但离目标仍远

归档 `3f8b9a0`，分析提交 `6c93291`。放开全局 40K 限制，SenseNova 6.8 Flash Lite 按配置原生 262144 上下文运行，输出上限 16384，深查预算提高到 200000、工具轮数增加，新增任务级恢复、进度/心跳和更强门禁。

注意：放开请求容量不等于每次都给了模型完整自然场景。场景焦点数、上下文半径、原文跨度和输出 schema 仍限制模型实际看到的信息。

首遍 6548/7009=93.42%，复审后 6602/7009=94.19%。复审修复 104、回归 50、前后都正确 27、错改错 22，净增 **54 条**。第 5 卷状态记录的当前进程复审调用数为 5398，却只净修复 3 条；该计数不宜未经汇总就声称覆盖所有历史重启进程。

407 条残余错误分布：

| 类型 | 数量 |
| --- | ---: |
| 实名与实名互换 | 189 |
| 泛称误判为错误实名 | 71 |
| 泛称与泛称不一致 | 52 |

正确答案丢失的位置更关键：202 条没有正确审阅候选，72 条有正确候选但未送陪审，133 条正确候选进了陪审却被门禁挡住。即使完美找回已有的 205 个候选，也只有 97.12%，仍不足 98%。候选生成和选择必须同时改善。

### 4.13 9 月之后：局部实体、恢复补丁与桌面化

归档 `359d37b` 等。为解决无名角色标签碎片化和场景外实名吸附，增加 `local_entity.py`、三路局部实体图、原文锚定、局部别名归并、场景外候选约束及更细的改写门禁。

同时，结构化结果失败导致复审反复卡住，于是逐步增加容错解析、枚举归一、格式序列化、批次拆分、单目标恢复、紧凑结果与任务弃权。这些措施解决“运行失败”，但也新增请求和分支；不能把“终于跑完”当成质量提升。

桌面版新增五卷继续/重跑/重试、进度、备份、托盘、启动配置与日志入口。随后修复 ETA、Windows GBK 输出、EXE 项目根目录、统一模型代理接入，以及 Windows 原子替换遇文件占用时失败。详见第 7 节提交索引。

| 07-26 场景/对抗层 | 修复 190，改坏 364，净 -174 | 更复杂的证据名称不代表更可靠的信息 |

### 5.3 当前实际执行链

当前默认质量路径可以概括为：

```text
小说/引号实例索引
  -> 逐句 Labeler + 原文工具 + 短记忆/证据库
  -> 场景 Mapper + 目标调查 + 反证/边界仲裁 + 保护门
  -> 身份搜索与标签规范化
  -> 首遍逐条提交
  -> 全卷 scene-review：每个场景块 9 个审阅任务
  -> local-entity-graph：每个场景块 3 个实体图任务
  -> 候选晋级与聚合
  -> 镜像陪审：每个入围替代候选最多 4 类职责 x 2 种顺序
  -> 多种转换门槛与最终发布
```

上述是逻辑任务数，不是固定物理请求数。工具循环、结构化失败、Serializer、批次拆分、任务重试和 API 恢复都可能放大请求数；场景缓存又会减少部分重复工作。

这是维护负担最大的地方：同一个说话人问题在多个层级重复求解，失败恢复也分布在多个层级。底层同一模型即使使用不同接入身份，仍不是多个独立模型。新框架若只是把上述链条原样搬过去，不会自动解决问题。

### 5.4 应保留与应重新审查的边界

值得保留：稳定对话 ID、精确引号位置、只读原文工具、输入输出隔离、正式/临时追踪、断点续跑、first-pass 快照、原子发布、备份去重、人工差异核查及作品专名扫描。

需要重新证明必要性：逐句深查后再整卷重复审阅、多个近似 Mapper、镜像票数门禁、旧决策模式长期并存、过多通用语言正则、手写结构化修复和各层独立重试循环。

“自研必然臃肿”不是结论；真正的问题是没有持续用消融实验淘汰无效层。基础设施适合借助成熟实现，小说归属语义仍需自身评测和设计。

## 6. 评估体系本身也要整理

1. **固定答案版本。** 保存原文、答案、对话索引和评分器哈希；人工纠正答案后，同时重算旧结果和新结果，不能只报新分数。
2. **别名评分防止循环验证。** 运行时 `verified` 是系统断言，不等于人工真值。主要基准应使用冻结、独立核验的身份关系，运行时别名口径作为辅助报告。
3. **记录无标签变化但评分变化的样本。** 本地 09-01 分析中，总正确数相比 08-15 增加 63，但只统计标签实际变化的对照净值为 47。脚本给各轮加载各自别名库，并跳过相同标签；差额 16 表明评分状态变化也参与了总分变化。它不能全归因于输出改进，也不能直接断言评分变化错误。
4. **只比较相同完成状态。** 第一遍分数、最终分数、部分区间分数分开；已标满不代表第二遍完成。
5. **全卷均值以外看错误簇。** 例如 09-01 第 4 卷 D201-D300 为 65%，第 5 卷 D201-D300 和 D801-D900 都为 67%。低谷需要整段分析，不是抽前 100 条。
6. **分离四个问题。** 人物性判断、局部说话实体、跨场景身份链接、最终标签渲染分别计错，不让一个含混“准确率”掩盖原因。
7. **报告回归。** 必须同时列修复数、改坏数、净收益、弃权率、候选召回率和候选选择失败位置。
8. **防止对五卷过拟合。** 同系列五卷可作为当前验收，但不足以证明跨作品泛化。即使没有写角色名，按同一批错误不断添加规则也可能特化；需留出未参与调参的场景，后续另准备有人工答案的其他作品。
9. **保留争议清单。** 非人物边界、具名时点和无名同义标签需要明确标注规范，不应自动扩大答案来迎合当前输出。
10. **测试通过不等于质量达标。** 单元测试保证恢复与协议等行为，不证明文学对话归属正确；精选难例成功也不代表全卷成功。

## 9. 下一阶段要调研什么

本节只是待办与实验设计，未在本次联网查阅、安装或试用任何外部 Agent 项目，也未验证其最新功能、许可证或维护状态。

### 9.1 调研对象与边界

用户提到的 WorkBuddy、Codex、OpenCode、CodeWhale-TUI 可作为使用体验或执行机制的对照对象，但不能预设它们全部开源、全部可嵌入、全部支持同一模型或相同多 Agent 方式。是否可复用必须逐项查证。

框架层也可把 LangGraph、PydanticAI、AutoGen、CrewAI 等列为候选检索词，但这里没有对其当前能力作结论，也没有选型。既要研究直接运行成熟 Agent 工具的最小基线，也要研究可嵌入的编排/状态组件，避免为了用框架而再次增加一层复杂度。

重点不是寻找题材相同的软件，而是寻找能复用的基础设施：

| 调研问题 | 需要拿到的证据 | 对本项目的价值 |
| --- | --- | --- |
| Agent 执行循环如何设计 | 原文读取、工具选择、停止条件、最终产物示例 | 避免手写大量强制轮次与相似代理 |
| 子任务怎样分解和汇合 | 多 Agent 上下文隔离、产物共享、冲突处理实现 | 判断是否真的增加信息，而非同模型重投票 |
| 上下文与长期记忆怎样管理 | 原文索引、检索、压缩、来源追踪、缓存边界 | 防止记忆把旧猜测升级为事实 |
| 结构化输出怎么验证 | schema、验证错误反馈、有限修复与拒绝机制 | 替换散落的手写解析、枚举猜测和 Serializer 循环 |
| 长任务怎样持久化 | task ID、checkpoint、幂等、取消/恢复、原子提交 | 保留现有可恢复性而减少定制分支 |
| API 请求怎样调度 | 超时、退避、限流、错误分类、队列和可观测性 | 不在代理、SDK、任务层重复无限重试 |
| 轨迹如何记录与回放 | 调用树、输入来源、token、耗时、失败原因 | 量化每一层的成本和净收益 |
| 桌面端如何接入 | 无头运行、进度事件、后台任务控制 | 复用现有 GUI，避免 GUI 绑死模型内部逻辑 |
| 是否适合长期维护 | 许可证、版本固定、依赖、Windows、测试和升级成本 | 单人可维护性是选型条件，不只是功能列表 |

### 9.2 先做最小强模型基线，不先设计更多 Agent

建议下一阶段的第一个问题是：**在同一批场景和同一个 DeepSeek V4 Flash 下，一个具备原文工具的简洁 Agent 能做到什么程度？**

应分别比较这些配置，而不是一次同时换模型、框架、提示词和评分器：

1. 冻结的现有系统及已完成历史输出，作为回归参照。
2. 简洁单 Agent，加较大原文窗口、必要的读取/搜索工具和明确输出 schema，不加复杂投票。
3. 成熟 Agent 工具执行同样的任务契约，允许其正常使用工具与任务分解能力，但不能读到答案文件。
4. 一个职责真正不同的复核 Agent：只查原文反证与冲突段，不重做所有简单样本。
5. 只有以上有明确收益后，才试更复杂的多 Agent、全局身份或场景级联合求解。

切换模型与切换执行器的效果要分开解释。必要时保留小规模同模型新旧架构对照，而不是让旧模型/旧框架对新模型/新框架后就把提升全归功于框架。

### 9.3 小说任务的关键研究问题

- 标注单位究竟应是精确引号、自然话轮、重叠场景还是章节？应通过实验决定，不继续默认每句都要走完整重型流程。
- 能否先完整阅读一个自然场景，再一次输出稳定 speaker sequence，缺证据时才主动扩读，而不是先限制为很短片段再制造更多审查层？
- 如何分离发声类型、说话人、被问者、附近动作主体、被提及者和引用中的原始发言者？
- 是否需要一个精简的动态实体账本，而不是多套各自修改身份的记忆系统？实体合并与命名必须附可回查原文。
- 如何表示未知或歧义，而不强迫模型用高频人物填空？如何在全卷后续信息出现时只回访真正受影响的前文？
- 如何用新的原文证据修正错误，而不是只让同模型再说一遍？镜像一致、置信度和多数票都不能自动等价于正确。
- 能否把标签规范化放在身份已确定之后，减少“女孩/服务人员/某男子”等字符串变化对推理和评分的干扰？
- 跨场景实体链接能否成为有明确边界的可缓存子任务，而不是每条对话重新全文搜索？

### 9.4 公平实验与验收

先建立冻结的分层样本集，包含：旧基线正确却被改坏的保护样本、候选已有正确答案却被拒绝的选择样本、所有候选都错的召回样本、人物性边界、动态身份，以及同场景随机正确对照。

模型运行环境应只包含允许读取的原文和工具，不把答案放在一个通用 coding agent 可以自由浏览的目录中。“提示词说不要看答案”不足以构成隔离。

建议逐步放大：代表场景回放、未参与提示调参的留出场景、单卷、最后前五卷。少量样本至少重复运行以观察波动；不能再次因为 10/10 就直接宣布值得进行几天的全卷重跑。

每个方案统一报告：

| 维度 | 必报内容 |
| --- | --- |
| 质量 | 每卷严格/冻结语义准确率、各类错误、最差场景窗口 |
| 修正价值 | 修复、回归、净收益，原本正确样本的保护率 |
| 信息价值 | 正确候选召回、无正确候选数、选择失败数、新增证据来源 |
| 稳定性 | 格式失败率、工具失败率、弃权率、恢复后是否重复工作 |
| 成本 | 首遍/复审/格式修复/失败重试各自的调用、token 和耗时 |
| 等待 | 模型服务时间、TPM/RPM 等待、网络重试、客户端开销分别统计 |
| 可维护性 | 自研组件数、配置复杂度、依赖与升级风险、运行可复现性 |

这里记录成本不是为了追求最低成本，而是要确认每一层是否值得保留。没有正净收益的层默认不进入新默认路径；收益不确定的层应是可关闭实验，而不是又一个永久主流程。

## 10. 重构的建议边界与交接顺序

本节不是已执行的改造，也不是提前承诺某个框架。

1. 冻结当前代码、五卷输入、答案口径、完整历史产物和本次未完成产物，建立实验索引。
2. 调研通用 Agent 工具与可嵌入组件，先核验模型兼容、状态恢复和安全读取边界。
3. 接入计划中的 DeepSeek V4 Flash，完成普通输出、工具调用、结构化输出、长输入和失败恢复的小规模测试。
4. 建立简洁强模型基线，与现有系统在相同样本上对照，先找出错误究竟源于模型、信息组织还是决策门。
5. 只保留有净收益的领域模块；把成熟库已经解决的编排、校验、追踪和持久化能力逐项替换，避免一次性大迁移失去可回退基线。
6. GUI 面向统一任务协议，只负责启动、取消、恢复、进度和备份；不要依赖 stdout 猜测复杂执行链是否完成。
7. 在证据支持后再跑前五卷，按每卷 98% 验收，同时保留跨作品泛化风险说明。

最重要的交接结论是：**下一阶段不是继续给 V4 增加更多审阅者，而是重新建立可复现的强模型基线，调查可复用的 Agent 基础设施，再用实验决定哪些步骤真正提高正确率。**
