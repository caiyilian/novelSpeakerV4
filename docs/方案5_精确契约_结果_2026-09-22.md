# 方案5（09-46 精确契约 + 证据强制）结果记录

记录日期：2026-09-22。分支 `feat/scheme-5-precise-contract`。方案来源：`docs/discussion/2026-09-21_09-46_Agent编排与12小时预算调研讨论.md`。

> **结论先行：方案5 = 94.36%，比方案2（普通仲裁 94.61%）低 0.25pp，净负。精确契约是"工程健壮性"改进，不直接涨分。**

---

## 一、方案做了什么

09-46 的核心主张：当前系统缺**可靠的任务定位契约**（quote id 只有行号，无同句序号/span），且**首遍丢证据、复核重新猜**。本方案在仲裁器层落地两个改动：

1. **精确引语定位**：用旧系统 `quote_occurrence.build_quote_occurrences` 的精确 span + 同句序号 + **scope_before/scope_after**（同一行引号前后文字），消除"同一行多引语"歧义（五卷共 16 个多引语行）。
2. **证据强制**：仲裁器必须输出**证据行号**且在原文范围内；无有效证据行则拒绝该条裁决（保留默认 cont）。同时把 parse 从"子串匹配"（`n in cand`，会把"不是罗伦斯而是赫萝"解析成罗伦斯）改成**精确匹配**。

实现：`annotator/arbiter5_agent.py`（分歧检测/簇化同方案2）。

## 三、关键发现

### 3.1 证据强制是双刃剑

- **正面**：v1 上 +0.52pp（该卷"带证据的裁决"质量更高）。
- **负面**：其余四卷略差——证据强制**拒绝了部分原本有效的裁决**（parse 要求"说话人+证据行号+依据"三段齐全，证据行号必须在范围内，说话人精确匹配），这些被拒的裁决里有相当一部分本来是对的。

### 3.2 精确契约的价值在"健壮性"，不在"涨分"

- 精确 span + scope 定位**没有直接涨分**——因为 cont/ev 的产物本身就是"行号定位"的，多引语歧义只影响 16 行 34 条，量级太小。
- 它的价值是**工程健壮性**（可审计、可回放、可复现），这正是 09-46 反复强调的，但**不等于准确率提升**。

### 3.3 与 09-46 判断的对照

09-46 正确地诊断了"解析能悄悄改变原意"（`n in cand` bug）和"证据被丢弃"两个缺陷。但这两个缺陷在**仲裁阶段**的影响有限——它们主要损害**首遍标注**（cont_agent 内部），而仲裁阶段拿到的是"已解析的干净标签"，修复这些 bug 的边际收益很小。

---

## 四、结论

1. **方案5（精确契约 + 证据强制）：94.36%，净 −0.25pp，不采用。**
2. 精确契约是**工程健壮性**改进，不是**涨分**机制。
3. **可复用**：精确 span 定位（`quote_occurrence`）+ 严格 parse（精确匹配）应进入**最终生产系统**（消除歧义、可审计），但**不指望它涨分**。
4. 证据强制要**调松**：允许"缺证据行但说话人明确"的裁决保留，而非一刀切拒绝。
