## 4. 主要错误簇

按已验证别名和姓名包含关系去除假错误后，最大的真实错误仍是核心对话双方互换：

- 第一核心人物误标为第二核心人物：76 条。
- 第二核心人物误标为第一核心人物：46 条。
- 有名人物与 `非人物发声` 相互误判：多卷重复出现。
- 连续两句被整体错位或交换，例如前一句和后一句的说话人恰好互换。
- 同一未命名人物被输出为不同外貌或职业描述，身份大体正确但规范标签错误。
- 已验证别名被验证器当作错误，包括简称、完整姓名、职业身份和化名之间的等价关系。

这里列出的角色互换仅用于解释本次数据，不会转化为源码中的角色名规则。系统必须继续保持通用小说适配能力。

## 5. 现有多 Agent 架构为何没有继续提升

本轮正式日志显示：

- 初始基线总体约为 92.14%。
- 最终结果中，基线错、最终改对只有 8 条；基线对、最终改错 3 条。
- `scene-evidence-baseline-retained` 占 6987/7009。
- 每条正确样本平均约 16.47 次模型调用，错误样本反而约 17.97 次。

也就是说，大量额外调用主要在记录分歧，几乎没有形成有净收益的决策。

直接恢复“多数意见覆盖基线”也不可行：现有场景映射、调查员、Judge 和对比边界虽然常常高置信一致，但单独准确率约为 89.8% 至 92.8%。离线模拟中，盲目采用对比边界会修复 197 条现有错误，同时破坏 333 条现有正确结果。

## 6. 根因

### 6.1 当前系统并不知道目标是同一行中的第几个引号

对话抽取保留了行号和文本，但本地证据分析只扫描目标前后若干整行，并把附近所有“某人说/问/回应”正则结果混在一起。一个叙述行有多个引号时，程序没有稳定记录每个引号的起止位置、前置叙述和后置叙述。

因此，属于上一句的后置 attribution 很容易污染下一句；属于目标引号的下一行延迟说明也可能被忽略。

### 6.2 attribution 正则召回过宽

当前正则会从反问、抽象说明和动作叙述中截出伪说话人，例如把“还用说吗”或“笑笑说”附近的文本片段当作人物。错误候选进入提示词后，会被多个同源 Agent 重复放大。

### 6.3 场景审阅发生得太早

场景第一次遇到时就被求解并缓存。此时后续对话尚未完成暂定标注，审阅器看不到完整的说话人序列，也无法从卷末回看卷首。对连续两句互换、延迟归因和身份后揭示尤其不利。

### 6.4 同一模型的高票数不是独立证据

所有角色虽然提示词不同，但底层模型、原文窗口和候选生成高度相同。多个 Agent 一致时仍可能只是共享同一错误锚点。下一阶段不能再把调用次数或票数本身当作质量保证。

## 7. 本轮后的改造方向

1. 建立精确引号实例账本：为每条对话记录全卷序号、原文行号、同一行引号序号、字符区间、引号前后叙述片段。
2. 清理伪 attribution：将反问和“无法/不用/怎么说”等非归因结构从候选中排除；高风险正则结果只作为待核查提示，不直接覆盖。
3. 完成第一遍全卷标注后再做第二遍：让审阅器看到完整暂定标签序列，以重叠场景同时重判多句，而不是逐句孤立投票。
4. 二次复核采用正序、逆序、精确引语作用域和基线反证四种不同任务；只有出现可靠替代候选时才启动目标级独立终审。
5. 二次复核使用独立日志、状态和 first-pass 快照，支持断点续跑；全部完成前不覆盖 `labeled.txt`。
6. 内置验证读取证据库中已验证的别名组，单独报告 `verified-alias`，避免把真实提升隐藏在字符串差异中。
7. 继续执行源码角色名扫描。任何 Python 源码都不得硬编码某一部小说特有的姓名、组织名或场景规则。

## 8. 结论

本轮从 88.84% 提升到 92.21%，按已验证身份关系为 92.75%，方向比上一轮更好，但尚未达到可接受目标。当前限制不是调用次数不足，而是“目标引号定位不精确”和“审阅时看不到完整暂定序列”。下一版应改变信息组织和复核时机；继续增加同形态 Agent 或简单放宽覆盖门槛不会稳定接近 98%。

## 9. 已实施改造与定点盲测

本次分析后已经实现以下改造：

- `quote_occurrence.py`：逐个记录对话序号、同一行引号序号、字符区间和前后叙述作用域，并在第一遍提示词中显式标出精确目标。
- `volume_review.py`：第一遍全卷完成后自动启动可断点续跑的第二遍；每 8 条焦点对话带前后重叠上下文，执行正序、逆序、引语作用域、对话行为、轮次边界、持有发言权和基线反证审阅。
- 只有至少两个独立审阅器提出有引用的替代候选，才启动三路目标终审；只有三路终审一致且证据类型、置信度和引用均合格时才覆盖第一遍。
- 第二遍开始时保存 `labeled.first_pass.txt`；审阅结果写入独立正式/临时日志和状态文件，全部完成前不修改 `labeled.txt`，完成后使用原子替换。
- 内置验证现在支持方向性的已验证别名：角色泛称答案可以升级为已证实姓名，但姓名答案不能降级成职业或外貌泛称。
- API 返回不规范枚举时做受限规范化；结构化结果截断或解析失败至少重试三轮，已完成的审阅块不会重跑。

使用 SenseNova 池进行了不向提示词提供参考答案的定点盲测：

1. 在一个八句高风险窗口中，七条原本正确的控制样本全部保持稳定；错误目标有三个盲审 Agent 提出参考答案中的说话人，但两名终审仍支持旧标签，因此保守门槛不会贸然改写这一处有歧义样本。
2. “犹豫/缺词后由另一人自报姓名”的样本中，多数模型仍错误合并连续两句。加入通用确定性约束后，五卷仅命中 1 条，离线结果为修复 1、破坏 0。
3. “一方声明离席、另一方回以告别、前一方随后离开”的样本中，六个模型审阅器仍错误合并。加入通用礼貌会话约束后，五卷同样仅命中 1 条，离线结果为修复 1、破坏 0。

这些定点结果证明第二遍提供了新的候选召回能力，也再次证明 SenseNova 的高置信一致本身不可靠。当前实现选择“模型负责开放式候选，严格终审负责高精度覆盖，极稀疏的结构规则处理可证明会话链”。实际总准确率提升仍必须由下一次五卷完整重跑衡量，不能用定点样本代替全卷结论。
