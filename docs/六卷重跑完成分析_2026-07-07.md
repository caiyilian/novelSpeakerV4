# 六卷重跑完成分析（2026-07-07）

本报告分析本次已经跑完的 6 卷：第 1、2、3、4、5、8 卷。

需要先强调两点：

- 本次完成的日志显示，每一卷仍然是固定使用一个 `sensenova-6.7-flash-lite-N`：第 1 卷用 `sense-nova-1`，第 2 卷用 `sense-nova-2`，以此类推，第 8 卷用 `sense-nova-6`。也就是说，本报告分析的是“固定 key 跑法”的结果，不是后续新加的 sense-nova 多 key 轮询结果。
- 第 1 卷答案是人工深度校对过的，可信度最高；第 2、3、4、5 卷已经经过本轮人工复核并覆盖 `answers.txt`；第 8 卷目前没有上一轮对照基线，准确率和错误类型需要结合后续人工核查看。

- 仍有少量 `failed_all`、`round_failed`、`no available api fallback model` 等情况。

## 六、风险复核机制的表现

本次六卷风险复核统计：

| 项 | 数量 |
|---|---:|
| RiskVerifier 确认原答案 | 3489 |
| RiskVerifier 不同意原答案 | 215 |
| RiskVerifier 跳过 | 2 |
| 实际应用修正 | 144 |

表面看，RiskVerifier 是在少数高风险场景才应用修正，但从对比旧版结果看，这 144 次修正并不稳定。尤其第 8 卷，24 次修正里只有 4 次修正后正确，20 次修正后仍错或被改坏。

观察到的风险复核问题：

- `explicit_attribution high` 过度自信。模型容易把附近出现的名字、被提到的人、被评价的人当作说话者。
- `alternation high` 有收益但也会害人。双人轮流说话的规律在小说对话中经常被插叙、动作、心理描写打断。
- 对 `非人物发声`、`旁白`、`叙述` 的处理不够保守。心理活动、标题式短句、叙述性句子容易被强行归到附近角色。
- 对“有名字角色 vs 泛称”的处理不够强。比如 `艾凡 -> 少年`、`诺儿菈 -> 牧羊女` 应该优先被纠正；但 `店主 -> 泰德•雷诺兹` 是否算错需要先确认该卷答案口径。

因此，后续不宜继续扩大自动修正的权限。更合理的方向是：

- Labeler 可以继续接收结构提示和候选证据。
- RiskVerifier 应更多作为“拦截明显错误”的保守复核，而不是主动改成另一个角色。
- 只有在存在直接引号归属、明确动作归属、已知别名映射、或当前段落强证据时，才允许覆盖原结果。
- 对心理/旁白/叙述类句子，应该提高改成人物的门槛。

## 七、当前最需要解决的问题

### 1. 主要角色互换仍是第一大问题

六卷里 `罗伦斯 -> 赫萝` 84 次，`赫萝 -> 罗伦斯` 57 次。只要这类错误还在几十次量级，系统就不可能接近 100%。

这不是某个特定小说名规则能解决的问题。通用规则应该是：

- 当前句如果是引用发言，必须找直接发言线索。
- 当前句如果是心理或叙述，不能只因为上下文有某角色就归给该角色。
- 双人对话的轮流规律只能作为弱证据，不应压过动作、称谓、语气、语境。

### 2. 有名字角色不能被泛称替代

用户已经明确要求：只要角色有名字，就必须用名字。`贤狼赫萝` 算赫萝，`磨粉匠艾凡` 算艾凡，但 `艾凡 -> 磨粉匠` 或 `艾凡 -> 少年` 不应该算对。

这条应该进入通用标注原则，而不是写死某部小说角色名。可以依赖 roster / evidence 中抽取出的别名和称谓：

- 如果泛称能唯一映射到当前人物，并且该人物有名字，最终输出应归一为名字。
- 如果只是未知路人，没有名字，则保留 `村民`、`酒吧客人`、`男子`、`女服务生` 等泛称。

### 3. 非人物发声边界需要更稳

`非人物发声 -> 罗伦斯`、`罗伦斯 -> 非人物发声`、`旁白 -> 罗伦斯` 这类错误说明系统没有稳定区分：

- 真实说话
- 心理活动
- 叙述句
- 标题/牌匾/文字内容
- 拟声、环境声、群体噪音

这部分需要增加保守门槛。特别是没有明确发言者的句子，不能仅靠最近角色或主题角色强行归属。

### 4. 泛称粒度问题需要分层处理

`女服务生 -> 红发女孩`、`乞丐 -> 男子`、`酒吧客人 -> 村民` 这类不一定是“说话人推理失败”，有时是答案口径问题，有时是模型没有选更合适标签。

建议不要写“商行/追兵/磨粉匠”等特定规则，而是做通用层级：

- 名字 > 稳定身份称谓 > 临时外貌称谓 > 泛化性别/人数称谓。
- 如果候选里存在更具体且已被当前场景确认的标签，不输出更泛的称谓。
- 如果没有名字或稳定身份，则允许泛称。

## 八、下一步建议

下一轮代码方向建议如下：

1. 启用 sense-nova 多 key 轮询，以降低运行层面的不稳定。这个改动影响调用分配，不直接承诺准确率提升。
2. 收紧 RiskVerifier 自动改写权限，尤其是 `alternation` 和 `explicit_attribution` 场景，不满足强证据时只记录风险，不覆盖答案。
3. 加强“有名字角色优先输出名字”的通用归一化，不硬编码罗伦斯、赫萝、艾凡等任何特定小说角色名。
4. 对 `旁白`、`叙述`、`非人物发声` 建立统一验证口径，同时在标注阶段提高从非人物改成人物的门槛。
5. 保留错误高亮文件和分卷报告作为人工核查入口，尤其第 8 卷需要先确认参考答案口径。

目前最重要的判断是：这次重跑结果说明“更复杂的结构复核”没有自动带来提升，反而可能让模型在弱证据场景更自信地错。后续要把流程从“多 agent 主动改”调回“强证据才改、弱证据保守”的方向。
