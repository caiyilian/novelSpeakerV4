# 重构准备八：多轮 Agent 方案最终验证与成绩

记录日期：2026-09-21。本文收敛第 9–15 轮的工作：按用户方向，从"整卷一次读"转向"多轮 Agent + 账本 + 阈值压缩"，并给出最终成绩。

---

## 1. 方案演进

用户的关键纠正（第 9 轮）："12 小时"是**单卷**预算；应像真实 agent 工具那样做**持续多轮对话 + 阈值压缩**，而非把整卷塞进一次调用。

据此构建了 `cont_agent.py`：

| 组件 | 做法 | 借鉴来源 |
| --- | --- | --- |
| 逐条多轮 | 按编号顺序标注，追踪"谁上一句说" | 旧系统 ShortMem / 用户描述 |
| 角色账本 | 预载 twopass 账本（canonical + 别名），边标边累积 | 旧系统 CharacterState |
| 阈值压缩 | token（`usage.prompt_tokens`）超 60 万即蒸馏历史成账本 + 最近锚点 | Codex CLI 本地压缩 |
| 断点续跑 | 每 50 条 checkpoint + `--resume` | 重启零丢失 |

## 2. 最终五卷成绩（权威口径）

| 方案 | v1 | v2 | v3 | v4 | v5 | 五卷 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 单次基线 | 90.9 | 90.1 | 91.6 | 85.7 | 83.8 | 88.23% |

**多轮 Agent = 92.31%，是当前最好方案**，五卷并行约 4 小时（单卷 ~3.5 小时，远低于 12 小时预算）。

---

## 3. 两个核心洞察

### 3.1 多轮 Agent 在难卷显著更强，且逐卷更均衡

多轮 Agent 把最难的两卷 v4/v5 从 89.0/88.3 拉到 **92.4/92.7**（+3.4/+4.4pp），代价是 v1/v2 略降。它把逐卷方差从「83.8–95.1」压缩到「88.6–94.7」——**用简单卷的小幅回撤，换来了难卷的大幅提升**。

### 3.2 「无人称引语」是双刃剑（最重要的洞察）

| | 整卷一次读 | 多轮 Agent |
| --- | --- | --- |
| 无人称引语倾向 | **欠检测**（把非人标成人） | **过检测**（把人标成非人） |
| 在非人物多的卷（v4/v5） | 大量欠检测 → 错 | 过检测正好修正 → 对 |
| 在非人物少的卷（v1/v2） | 影响小 | 过检测误伤真对话 → 错 |

这就是多轮 Agent 在 v4/v5 赚、在 v1/v2 亏的根因，净 +0.84pp。

## 4. 与整卷方案的互补分析

对 7009 条逐一对比：

| 情形 | 条数 |
| --- | ---: |
| 两方案都对 | 6075 |
| 多轮独对 | 395 |
| 整卷独对 | 336 |
| **两方案都错** | **203** |

- 多轮独对（395）> 整卷独对（336），所以简单"分歧信多轮"已是 92.31%。
- **两方案都错的 203 条是共同盲区**——真正的无人称引语、复杂实名互换、泛称口径。这是从 92.31% 迈向 95% 的关键，也是当前唯一没被攻克的硬骨头。

---

## 5. 结论

1. **多轮 Agent 方案成立，92.31%，当前最好**。这推翻了我第 6 轮"v4-flash 干净方法天花板 ~91.6%"的判断——多轮 + 账本 + 阈值压缩确实能更上一层。
2. **离 95% 还差 2.7pp，离旧系统 94.19% 差 1.88pp。** 旧系统用十几天 + 每条约 15–18 次调用 + 弱模型补偿才到 94.19%；多轮 Agent 用 4 小时 + 强模型到了 92.31%。
3. **剩余瓶颈 = 两方案共同盲区 203 条**，集中在无人称引语的精确判定（既不能欠检测也不能过检测）。

### 下一步方向

1. **攻克 203 条共同盲区**：做一个"无人称引语"的精确判定器——不再是"欠检测/过检测"二选一，而是让模型在"拿不准是不是发言"时显式标记，再由一个专门步骤裁决。
2. **第三信号裁决分歧**：对 cont 独对/ev 独对的 731 条，引入第三个独立信号（如"逐句深查证据链"）来裁决，而不是盲选一方。
